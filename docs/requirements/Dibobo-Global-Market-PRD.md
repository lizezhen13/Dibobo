## 1. 文档目的与变更关系

本文档定义全球市场模块的产品范围、指标口径、信息架构、展示规则、AKShare 接入、后台刷新、缓存、新鲜度、市场状态、API 契约、异常降级、测试和验收标准。

本文档是产品、前端、后端、数据接入、测试和部署工作的共同需求基线。技术实现可以在不改变本文档用户行为、业务口径和验收结果的前提下调整。

### 1.1 对既有需求的专项补充

本 PRD 对既有需求形成以下专项补充：

1. 将总览面板现有“全球市场”空状态替换为四张可独立加载的行情卡片；
2. 在私有研究场景下，允许系统级 AKShare 独立承担全球市场公共数据；
3. 增加全球指数、外汇、国内外商品期货和主权国债收益率能力；
4. 增加全球市场在平板和移动端的响应式要求；
5. 增加不同国家、交易所、时区和数据频率并存时的状态与时间口径。

### 1.2 与多数据源网关 PRD 的边界

本功能不改变用户级数据源规则：

- 用户当前启用的扶摇或扶摇兼容源仍是 A 股业务主源；
- 全球市场 AKShare 数据不属于用户新增、编辑或启用的数据源；
- 全球市场快照按部署全局共享，不按用户复制或重复抓取；
- 本功能新增的全球市场能力不自动参与 A 股行情、持仓、雷达或自选的字段补全；
- Dibobo-Multi-Source-Data-Gateway-PRD.md 中“A 股指数不切换至 AKShare”的既有边界继续有效；
- 全球市场可复用 Provider 注册、来源追踪、错误分类、缓存、锁和后台任务基础设施。

## 2. 背景与问题定义

### 2.1 当前状态

总览面板已经存在“A 股市场”和“全球市场”两个 Tab。“全球市场”当前只有一个整卡空状态，提示数据暂未接入，没有实际内容、数据类型或交互。

项目已经固定依赖 AKShare 1.18.84，并具备系统级 AKShare 适配器、后台任务、Valkey 快照和多数据源网关基础能力，但现有 AKShare 适配器仅正式处理 A 股公共快照，尚未定义全球市场领域模型与能力。

### 2.2 核心问题

全球市场不是单一交易所行情，必须同时处理：

1. 亚洲与美国指数的不同交易时段和节假日；
2. 24×5 外汇与贵金属现货；
3. 国内日盘、夜盘和海外期货；
4. 主连合约的动态映射和换月；
5. 日频国债收益率与实时行情并存；
6. 不同 Origin 返回的代码、时间、单位和字段差异；
7. 上游网页变化、限流、超时、缺项和延迟；
8. 一组失败时其他组仍需正常展示。

## 3. 产品目标与成功标准

### 3.1 产品目标

1. 在一个 Tab 中一次性呈现 21 项已确认的全球市场指标；
2. 用户无需进入详情页即可理解最新值、涨跌方向、报价单位和市场状态；
3. 四张卡片独立加载、独立失败、独立降级；
4. 所有公共行情从后台共享快照读取，不因用户数量增加而重复抓取；
5. 所有主连品种可以追溯到当前实际映射合约；
6. 所有数据可以追溯到 Provider、Origin、供应商代码、行情时间和抓取时间；
7. 上游不可用时保留明确标记的最后成功数据，不显示虚构值；
8. 为未来替换成合规商业数据源保留稳定领域边界。

### 3.2 成功标准

- 全球市场 Tab 同时包含全球指数、汇率情况、全球商品、国债收益率四张卡片；
- 正常响应固定包含 6 个指数、3 个汇率指标、8 个商品和 4 个国债期限；
- 页面不出现迷你走势图、内部 Tab、分页或默认折叠；
- 所有字段、代码、精度、单位、报价方向和涨跌基准符合本文档；
- 单项缺失不会改变其他项目的位置或导致整卡失败；
- 后台同一刷新窗口、同一数据组最多执行一次 AKShare 上游抓取；
- 页面请求只读缓存，不在 FastAPI 请求链路同步调用 AKShare；
- 21 项供应商映射全部通过真实网络验收后方可发布。

## 5. 术语与核心原则

### 5.1 术语

| 术语 | 定义 |
|---|---|
| 产品代码 | Dibobo 面向用户展示和内部稳定引用的代码，例如 IXIC、USDIND |
| 供应商代码 | AKShare 上游结果返回的代码，例如 NDX、UDI |
| Provider | Dibobo 接入的数据提供实现，本功能固定为 akshare |
| Origin | AKShare 实际访问的网站或机构，例如 eastmoney、sina |
| 行情时间 | 上游数据所代表的 quoted_at 或 as_of_date |
| 抓取时间 | Dibobo 完成上游调用的 fetched_at |
| 当前快照 | 最新一次通过质量校验并正式发布的标准化数据 |
| 最后成功快照 | 当前抓取失败时可用于降级展示的最近成功数据 |
| 主连 | 按供应商规则连续跟踪当前主力合约的产品视图 |
| 映射合约 | 主连在当前时点实际指向的月份合约 |
| bp | 基点，1 bp = 0.01 个百分点 |

### 5.2 核心原则

1. 产品代码稳定，供应商代码可以替换；
2. 数据时间优先于抓取时间判断新旧；
3. 旧快照不得覆盖新快照；
4. 交易时段、休市状态和数据延迟必须分开表达；
5. 缺失值使用 null 和明确原因，不使用 0；
6. 上涨和下跌同时使用颜色、符号和方向图标；
7. 主连换月必须可追溯，不静默改变数据口径；
8. 单一数据组故障不得拖垮整个全球市场页面；
9. 后台任务负责上游抓取，HTTP 请求只读取已发布快照；
10. 任何供应商映射无法证明身份时，该项不得发布。

## 6. 信息架构与页面布局

### 6.1 页面入口

- 页面：总览面板；
- 路由：沿用 /overview；
- 一级 Tab：全球市场；
- 全球市场 Tab 内直接呈现四张卡片；
- 不再使用一张“全球市场”外层卡片包裹四张子卡片。

### 6.2 页面工具栏

四卡网格上方提供一条轻量工具栏：

- 数据源摘要：AKShare；
- 页面级刷新按钮；
- 刷新中状态；
- 当全部数据组不可用时的页面级提示。

页面级刷新按钮只重新读取后端已发布快照。若后端当前快照需要刷新，应由后台任务和分布式锁完成；连续点击不得直接制造上游并发请求。

### 6.3 桌面端布局

宽屏采用 12 列网格：

| 行 | 左侧 | 右侧 |
|---|---|---|
| 第一行 | 全球指数，占 8 列 | 汇率情况，占 4 列 |
| 第二行 | 全球商品，占 8 列 | 国债收益率，占 4 列 |

内部排列：

- 全球指数：亚洲 3 项一组，美国 3 项一组；
- 汇率情况：3 项纵向排列；当卡片变为全宽时可转为 3 列；
- 全球商品：伦敦现货、纽约期货、国内期货、能源四组，每组 2 项；
- 国债收益率：中国与美国为列，1 年与 10 年为行，形成 2×2 对照。

### 6.4 响应式要求

| 视口 | 布局要求 |
|---|---|
| 大于等于 1280 px | 8+4 两列布局 |
| 768–1279 px | 四张卡片单列排列，卡内按可用宽度增加列数 |
| 小于 768 px | 四张卡片单列；指数和商品优先使用 2 列；汇率使用 1 列；国债保持 2×2 |

所有宽度下必须满足：

- 不出现页面级横向滚动；
- 数值、单位和涨跌信息不互相遮挡；
- 卡片顺序固定为全球指数、汇率情况、全球商品、国债收益率；
- 缺项和加载状态不造成明显布局跳动。

## 8. 计算与数据语义

### 8.1 指数、汇率和商品涨跌

优先使用上游同一快照提供的最新值、涨跌值、涨跌幅和昨收或昨结。不得以北京时间 00:00 的数值自行作为比较基准。

当上游只提供最新值与昨收或昨结时：

    change = latest - previous
    change_percent = change / previous × 100

规则：

- previous 为 0 或 null 时，涨跌值和涨跌幅均返回 null；
- 不同来源或不同快照的 latest 与 previous 不得混算；
- 商品优先采用昨结；若目标品种明确使用昨收，需在映射中记录；
- 换月后的主连涨跌必须基于当前映射合约自身的昨结，不能拿上一交易日旧合约收盘比较。

### 8.2 国债 bp 变动

国债选择最新两个日期不同且收益率有效的记录：

    change_bp = (latest_yield - previous_yield) × 100

示例：

    最新收益率 1.846%
    上一发布日 1.834%
    change_bp = +1.2

规则：

- 保留至少 1 位小数；
- 没有上一有效发布日时返回 null；
- 收益率按百分数原值保存，例如 1.846 表示 1.846%；
- 不将 1.846 再乘以 100。

### 8.3 精度与舍入

- 后端保存上游有效精度，不为展示提前截断；
- 前端按本文档精度四舍五入；
- 涨跌幅统一显示 2 位小数；
- 涨跌值默认沿用最新值精度；
- 国债变动显示 1 位 bp，必要时允许显示更多有效位；
- null 显示为“—”，0 显示为真实的 0 或 0.00，不得混淆。

1. 名称、产品代码、市场状态；
2. 最新值与单位或完整报价方向；
3. 涨跌值、涨跌幅和方向图标。

国债行情项的视觉层级：

1. 名称和产品代码；
2. 最新收益率；
3. bp 变动和截至日期。

行情项暂不进入详情页，不应表现为整块可点击卡片。

### 9.3 数据说明浮层

鼠标悬浮、键盘聚焦或移动端点击状态信息时，显示：

- 完整中文名称；
- 产品代码；
- 供应商代码；
- Provider；
- Origin；
- 完整单位或报价方向；
- 行情时间或数据日期；
- 抓取时间；
- 当前映射合约；
- 数据新鲜度；
- 缺失或降级原因。

浮层必须可关闭、可键盘访问，并不得成为移动端读取数据时间的唯一障碍。

### 9.4 颜色与无障碍

- 上涨：现有 market-up 红色；
- 下跌：现有 market-down 绿色；
- 持平：中性色；
- 交易中：success 状态色；
- 延迟：warning 状态色；
- 中断或错误：danger 状态色或弱化文本；
- 国债收益率上升仍按数值方向显示红色，不表达利好或利空；
- 正负号和方向图标必须与颜色同时存在；
- 交互控件必须有可访问名称和可见焦点；
- 关键文字与背景对比度应满足 WCAG AA。

## 12. 系统架构与调用边界

### 12.1 数据流

    Celery 定时任务
      → AKShare 接口
      → 原始字段校验
      → 产品代码与单位标准化
      → 数据质量门禁
      → 发布当前快照与最后成功快照
      → 总览 API 读取 Valkey
      → 前端渲染四张卡片

### 12.2 强制边界

- FastAPI 的全球市场 GET 请求不得同步调用 AKShare；
- 前端不得直接访问 AKShare、东方财富或新浪；
- 定时任务不得按用户重复执行；
- 每个 Capability 独立刷新和发布；
- 每个 Capability 使用独立分布式锁；
- 一组刷新失败不取消其他组成功结果；
- 原始抓取异常不得阻塞登录、A 股总览、持仓、雷达或其他业务。

### 12.3 建议模块边界

后端建议划分：

- 全球市场领域模型与标准化函数；
- AKShare 全球市场适配器；
- 快照发布与读取服务；
- 刷新调度与分布式锁；
- 总览聚合服务与路由；
- 来源追踪与质量校验。

前端建议划分：

- 全球市场查询与类型；
- 全球市场页面网格；
- 四类卡片；
- 通用行情项；
- 国债收益率项；
- 状态与数据说明浮层；
- 格式化和响应式测试。

技术实现可以合并文件，但不得破坏上述职责边界。

## 14. 后台刷新策略

### 14.1 上游刷新

| 数据组 | 活跃时段 | 非活跃时段 |
|---|---|---|
| 全球指数 | 任一目标指数处于交易时段时每 60 秒 | 停止高频刷新；在预期开盘、收盘附近执行确认抓取 |
| 汇率 | 工作日 24×5 每 60 秒 | 周末停止高频刷新 |
| 海外商品 | 目标市场活跃时每 60 秒 | 休市或日内维护时段停止高频刷新 |
| 国内主连 | 日盘和夜盘每 60 秒 | 非交易时段停止高频刷新 |
| 国债收益率 | 日频；在预期发布日期推进前按受控间隔重试 | 日期推进后停止当日重复抓取 |

具体交易时段和调度时间必须配置化，不得把固定 UTC 偏移散落在业务代码中。

### 14.2 前端刷新

- 全球市场 Tab 可见时每 60 秒重新读取聚合接口；
- Tab 隐藏、浏览器后台或页面离开时停止轮询；
- 不在窗口重新聚焦时瞬间并发四次请求；
- 页面级手动刷新只触发一次聚合接口重新读取；
- 后台刷新期间保留现有数据。

### 14.3 单次抓取锁

- 锁粒度为 Capability；
- 同一 Capability 同一刷新窗口全局最多一个抓取任务；
- 锁 TTL 必须大于正常超时时间并小于硬过期时间；
- Worker 异常退出后锁可自动释放；
- 手动刷新不能绕过锁。

## 15. 缓存与新鲜度

### 15.1 缓存层级

每个数据组至少保存：

1. 当前正式快照；
2. 最后成功快照；
3. 当前刷新状态；
4. 最近错误；
5. 分布式锁。

最后成功快照保留 30 天。当前快照的 TTL 可以短于最后成功快照，但不得因 TTL 到期丢失降级能力。

### 15.2 实时类数据新鲜度

交易或活跃时段：

| 行情时间年龄 | freshness | 展示 |
|---|---|---|
| 小于等于 2 分钟 | fresh | 正常 |
| 大于 2 分钟且小于等于 10 分钟 | delayed | 显示“延迟”，保留正常可读性 |
| 大于 10 分钟 | interrupted | 显示“数据中断”，弱化最后值 |

规则：

- 年龄优先以 quoted_at 计算；
- 无 quoted_at 时使用 fetched_at，并在来源元数据中说明时间基础；
- 休市期间不按上述分钟阈值判定中断；
- 最近有效收盘属于最新完成交易时段时，状态为已收盘或休市；
- 不能确认交易日历时使用未知，不得猜测为交易中。

### 15.3 国债数据新鲜度

- 最新应发布日期存在：fresh；
- 最新数据尚未到预期发布时间：正常等待；
- 比预期发布进度落后 1 个工作日：stale，可继续展示；
- 落后 2 个及以上预期工作日：显示“数据滞后”；
- 数据日期判断必须按对应国家工作日与发布规律执行。

## 16. 市场状态与时间

### 16.1 时区

| 品种 | 市场时区 |
|---|---|
| 恒生指数 | Asia/Hong_Kong |
| 日经225 | Asia/Tokyo |
| 韩国综合指数 | Asia/Seoul |
| 美国三大指数 | America/New_York |
| 国内期货 | Asia/Shanghai |
| 海外商品 | 按实际交易所或报价市场配置 |
| 外汇 | 24×5 市场规则，展示统一使用 Asia/Shanghai |
| 国债日频数据 | 使用 as_of_date，不计算交易中 |

### 16.2 时间标准化

- 后端所有 datetime 使用带时区对象；
- 标准化快照中的 quoted_at 和 fetched_at 序列化为 UTC ISO 8601；
- 前端统一转换为北京时间展示；
- 上游“指数所在地时间”必须先按品种时区解释，再转换 UTC；
- 美国市场状态必须通过 America/New_York 处理夏令时，不使用固定 UTC-5；
- 只有日期没有时间的国债数据使用 as_of_date，不伪造 00:00 行情时间。

### 16.3 市场状态

普通行情允许：

- 交易中；
- 已收盘；
- 休市；
- 未知。

国债日频项使用“不适用”，页面显示截至日期而不是市场状态。

市场状态由配置化交易时段、交易日历和数据时间共同判断。若无法可靠获得节假日信息，优先显示未知或已收盘，不得错误显示交易中。

## 17. 主连合约规则

### 17.1 国内主连

- 每个中国交易日开盘前更新 SHFE 主力合约映射；
- 收盘后可再执行一次确认；
- AU 与 AG 分别保存产品代码、实际合约和映射时间；
- 行情抓取必须使用与本次映射相同的实际合约；
- 返回 mapped_contract，例如 AU2612、AG2612；
- 映射切换时记录旧合约、新合约和切换时间；
- 新合约行情不可用时，不得无标记回退到旧合约最新价。

### 17.2 海外主连

- 优先使用供应商连续合约记录；
- 供应商代码和连续语义必须在真实联调中确认；
- 若连续记录消失，项目进入缺失或缓存状态；
- 不自动切换到具体月份合约，除非开发阶段形成明确、可测试且经产品确认的映射规则。

### 17.3 换月展示

- 页面名称保持“主连”；
- 数据说明浮层显示当前映射合约；
- 换月本身不弹出提醒；
- 价格跳变不能被错误判定为解析失败，但应保留日志与来源信息。

## 18. 数据质量与发布门禁

### 18.1 基础校验

每个项目发布前至少校验：

- 产品 ID 在固定允许列表；
- 供应商代码符合已验证映射；
- 最新值为有限数值或明确 null；
- 涨跌字段为有限数值或明确 null；
- 单位和报价方向与产品配置一致；
- 数据时间不明显晚于抓取时间；
- 数据时间不早于当前已发布快照；
- 主连存在有效映射合约；
- 国债存在合法日期和最新两个有效记录。

### 18.2 覆盖校验

| 数据组 | 期望数量 |
|---|---:|
| 全球指数 | 6 |
| 汇率情况 | 3 |
| 全球商品 | 8 |
| 国债收益率 | 4 |

- 全部有效时 state=ready；
- 部分有效时 state=partial；
- 全部只能使用最后成功数据时 state=stale；
- 无有效值且无缓存时 state=unavailable；
- 缺失项目仍需生成固定槽位和 missing_reason。

### 18.3 映射门禁

正式发布前必须保存一组脱敏上游 Fixture，并完成：

- 6 个指数代码与名称验证；
- USDIND、USDCNH、HKDCNH 报价方向验证；
- 8 个商品的代码、名称、单位与连续合约语义验证；
- AU、AG 主力合约解析验证；
- 4 个国债期限和百分数单位验证；
- 纳斯达克综合指数与纳斯达克100身份区分验证；
- 布伦特原油与 WTI/NYMEX 原油身份区分验证。

### 18.4 不使用硬性涨跌阈值删除行情

金融品种可能出现异常大幅波动甚至特殊价格。系统可以记录质量警告，但不得仅因涨跌幅超过固定阈值就静默丢弃。只有身份、单位、时间或数值类型无法通过校验时才阻断发布。

## 19. 异常与降级

### 19.1 错误分类

至少区分：

- unsupported；
- missing；
- valid_empty；
- timeout；
- rate_limited；
- upstream_unavailable；
- schema_invalid；
- mapping_failed；
- quality_failed；
- cache_unavailable；
- internal_error。

### 19.2 降级顺序

    新鲜当前快照
    → 允许范围内的最后成功快照
    → 固定项目槽位 + 明确缺失

不允许：

- 使用其他相近品种替代；
- 使用 0；
- 使用上一项目的值；
- 使用不同日期或不同合约字段拼成一条行情；
- 隐藏失败项目；
- 把抓取时间当成行情时间而不说明。

### 19.3 Valkey 异常

- HTTP 请求不得因缓存异常转而同步调用 AKShare；
- 后台任务不得在 Valkey 不可用时发布无法共享的“临时成功”；
- 若应用进程没有可安全返回的快照，按组返回 unavailable；
- Valkey 恢复后由后台任务重新发布。

- 发布部署必须显式开启上述两个开关；
- global_market_enabled 与现有 A 股 AKShare shadow/serve 模式相互独立；
- akshare_mode 继续只控制 A 股网关中的 AKShare shadow/serve 行为，不控制全球市场；
- 关闭全球市场后停止新抓取，API 返回功能未启用状态；
- 开关不得改变用户当前启用的数据源；
- 配置变化后旧策略缓存不能被错误复用；
- AKShare 依赖版本继续由锁文件精确固定。

## 21. 后端开发要求

### 21.1 领域模型

新增能够表达以下差异的统一模型：

- 实时数值与日频收益率；
- change、change_percent 与 change_bp 的互斥关系；
- quoted_at 与 as_of_date；
- 产品代码与供应商代码；
- 现货、连续合约和动态主力合约；
- 市场状态与数据新鲜度；
- item 级来源和缺失原因。

### 21.2 Adapter

- AKShare 同步调用必须在线程池或专用 Worker 中运行；
- 导入失败、函数缺失、超时、空表、列缺失和解析失败映射为结构化错误；
- 不在模块导入阶段执行网络请求；
- 不依赖 DataFrame 列顺序；
- 中文列名和供应商字段统一在 Adapter 边界转换；
- 测试不得依赖真实网络。

### 21.3 任务

- 各 Capability 独立任务或独立可观测步骤；
- 调度任务只在启用时执行；
- 全局共享 single-flight；
- 失败重试采用有上限的退避，不做高频无限重试；
- 国债只取最新需要的窗口，不在每次刷新重复抓取全部历史；
- 主连解析与行情抓取必须保持一致性。

### 21.4 API

- 聚合读取不能等待上游；
- 组级 partial 不转换为整页错误；
- 响应字段必须通过 Pydantic 模型校验；
- 固定项目顺序由后端保证，前端不根据上游名称重新排序；
- 前端不需要理解 AKShare 原始字段。

## 22. 前端开发要求

### 22.1 组件

- 复用现有 Card、OverviewPanel 标题与状态语言；
- 不直接复用现有 IndexCard 的高低价、成交额布局；
- 全球市场行情项只展示本文档要求字段；
- 数字使用等宽字体和 tabular-nums；
- 卡片加载、异常和数据状态保持现有设计系统一致。

### 22.2 查询

- 建议一个聚合 query key；
- refetchInterval 使用后端 refresh_seconds；
- refetchIntervalInBackground=false；
- refetchOnWindowFocus 不制造重复请求；
- 后台刷新不清空已有 data；
- 页面级刷新按钮防重复点击并显示同步状态。

### 22.3 格式化

- 格式化函数必须覆盖每种精度、单位、汇率方向和 bp；
- null 统一显示“—”；
- 正数带“+”，负数带“-”；
- 0 使用持平样式；
- 极大数值不得挤压状态与单位；
- 所有时间按 Asia/Shanghai 展示。

## 23. 非功能要求

### 23.1 性能

- 全球市场聚合 API 只读缓存时 P95 目标不超过 200 ms；
- 首次打开 Tab 只发起一个业务聚合请求；
- 后台抓取不占用 FastAPI 事件循环；
- 上游慢请求不得拖慢其他业务；
- 多用户访问不增加同一刷新窗口的上游调用次数。

### 23.2 可用性

- 单组故障时其他组可用；
- 缓存存在时上游短时故障不导致空白页面；
- 页面刷新不闪烁、不回退到整页骨架；
- 功能关闭或无数据时保持稳定四卡结构。

### 23.3 安全

- 聚合接口沿用登录鉴权；
- 不向前端暴露内部代理、Cookie 或第三方请求细节；
- 不绕过 Origin 的访问限制；
- 不使用 IP 轮换、验证码规避或反爬绕过；
- 日志不记录用户敏感信息；
- 全球公共快照不包含 user_id。

### 23.4 合规

AKShare 官方说明其数据接口主要用于学术研究并提示商业风险。本功能当前仅适用于私有研究部署：

- 若 Dibobo 未来公开提供服务、收费或商业化，必须重新完成数据授权和法务评估；
- 未完成评估前不得把本功能描述为商业实时行情服务；
- AKShare 代码许可证不等于各 Origin 数据的商业授权；
- 页面应保留数据来源和数据时间，不暗示交易所直连。

## 24. 可观测性

### 24.1 日志

每次后台刷新记录：

- capability；
- provider；
- origin；
- adapter_version；
- 开始与结束时间；
- 耗时；
- 上游记录数；
- 目标命中数；
- 发布状态；
- 缺失产品；
- quoted_at 或 as_of_date；
- 错误类别；
- 是否使用最后成功数据；
- lock 获取结果；
- quality_profile。

### 24.2 指标

建议监控：

- 各 Capability 成功率；
- 刷新耗时；
- 连续失败次数；
- 当前快照年龄；
- 目标覆盖数量；
- mapping_failed 次数；
- schema_invalid 次数；
- 上游空表次数；
- 分布式锁冲突次数；
- 各组 stale 或 unavailable 持续时间。

### 24.3 告警

至少覆盖：

- 任一实时组连续 3 次刷新失败；
- 交易时段当前快照超过 10 分钟；
- 国债数据落后 2 个预期工作日；
- 供应商代码或列结构变化；
- 主连映射缺失；
- 当前正式快照无法读取；
- AKShare 依赖版本与锁文件不一致。

## 26. 发布与回滚

### 26.1 发布阶段

- 完成 21 项产品配置；
- 完成标准化模型；

- 完成单元测试。

- 观察覆盖、延迟、结构变化和任务稳定性；

- 展示四张卡片；
- 监控错误率、快照年龄和覆盖；

### 26.2 回滚

- 通过独立功能开关停止全球市场后台抓取；
- 前端回到明确的功能不可用状态；
- 不删除最后成功快照，保留排障和恢复能力；
- 回滚不影响现有 A 股数据源、缓存和页面；
- 不通过降级到其他未确认数据源规避故障。
