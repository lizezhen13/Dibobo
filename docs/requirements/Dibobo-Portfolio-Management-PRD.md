## 1. 背景

现有版本将持仓直接挂在用户下：同一用户、同一标的只能存在一条当前持仓。该模型无法区分不同投资策略、账户或资金用途，也无法分别查看多个投资组合的市值和盈亏。

本次将“持仓管理”升级为“投资组合”功能，引入投资组合这一层级：

```text
用户
├── 投资组合 A
│   ├── 当前持仓 1
│   ├── 当前持仓 2
│   └── 已清仓历史
└── 投资组合 B
    ├── 当前持仓 1
    └── 已清仓历史
```

组合汇总不是用户手工录入的数据，而是由组合内当前持仓和最新行情实时计算得出。

## 2. 产品目标

1. 用户可以创建和管理多个相互独立的投资组合。
2. 每个投资组合可以管理多只 A 股和 ETF。
3. 同一股票可以同时出现在不同投资组合中，但同一组合内只能有一条当前持仓。
4. 用户可以查看单个投资组合的当前持仓市值、浮动盈亏、已实现盈亏、累计总盈亏和持仓结构。
5. 组合汇总随组合内股票的数量、成本和最新行情动态变化。
6. 既有持仓数据迁移后仍然可用，且不丢失当前持仓和已清仓历史。

## 4. 用户与权限

1. 投资组合属于当前登录用户。
2. 用户只能读取、创建、修改和删除自己的投资组合及组合内持仓。
3. 用户之间的数据完全隔离。
4. 继续沿用现有登录、会话、CSRF 和接口鉴权机制。
5. 不新增组合共享或协作权限。

## 5. 核心概念

### 5.1 投资组合

用户用于归类和独立查看一组股票持仓的业务对象。

组合本身不保存资金账户余额，也不保存单独的收益数据；组合情况由当前持仓动态聚合得到。

### 5.2 当前持仓

组合中数量大于 0 的一条股票或 ETF 持仓记录，状态为 `open`。

### 5.3 已清仓记录

当前持仓数量修改为 0 并完成清仓确认后形成的历史记录，状态为 `closed`。记录保留在原投资组合中，不参与当前持仓市值和浮动盈亏汇总，但会参与已实现盈亏和累计总盈亏计算。

清仓记录保存清仓数量、清仓价格、清仓日期和操作时间。已有历史记录如果缺少清仓价格或数量，则已实现盈亏显示为“暂无数据”，允许后续补录。

### 5.4 标的

通过当前数据源检索得到的 A 股或 ETF。标的身份由完整 `thscode` 确定。

## 6. 页面与交互

### 6.1 页面入口

- 导航名称：`投资组合`。
- 页面标题：`投资组合`。
- 页面说明应表达：管理多个投资组合及其股票持仓，组合数据随行情动态更新。
- 推荐新路由：`/portfolios`。
- 旧路由 `/holdings` 应重定向或兼容到投资组合页面，避免已有入口失效。

### 6.2 页面布局

桌面端采用“组合列表 + 选中组合详情”的两层布局。

```text
投资组合页面
┌────────────────┬─────────────────────────────────┐
│ 投资组合列表    │ 当前选中的组合详情                 │
│                │                                 │
│ 我的组合       │ 红利组合  编辑 / 删除 / 设为默认    │
│ 长期投资       │ 总成本 / 总市值 / 浮动盈亏 / 盈亏率  │
│ ETF 组合       │ 当前持仓 / 已清仓                  │
│                │ 股票明细表                         │
│ + 新建组合     │ + 添加股票                         │
└────────────────┴─────────────────────────────────┘
```

具体规则：

1. 左侧或上方显示当前用户的全部投资组合。
2. 点击组合后，主区域切换到该组合的汇总和股票明细。
3. 新增股票时，股票添加到当前选中的组合。
4. 进入页面时优先选中默认组合；没有默认组合时选中排序第一的组合。
5. 没有组合时显示创建组合引导。
6. 当前组合为空时，显示空组合状态和“添加第一只股票”操作。
7. 移动端将组合列表放在组合详情之前，采用上下布局。
8. 组合列表中的组合顺序由用户设置的排序决定。
9. 组合列表至少展示组合名称、默认标识和当前持仓数量。

### 6.3 投资组合列表操作

#### 新建组合

点击“新建组合”后打开组合表单。

字段：

| 字段 | 必填 | 规则 |
|---|---:|---|
| 组合名称 | 是 | 去除首尾空白，不得为空，最多 50 个字符 |
| 备注 | 否 | 纯文本，最多 1,000 个字符 |

新建后：

- 组合立即出现在组合列表中；
- 新组合自动成为当前选中组合；
- 组合初始为空；
- 不自动生成任何股票持仓；
- 用户可以选择将其设为默认组合。

#### 编辑组合

- 可修改组合名称和备注；
- 不改变组合 ID；
- 不改变组合内股票和清仓历史；
- 保存后组合列表和详情标题立即更新。

#### 删除组合

- 删除前必须二次确认；
- 确认后级联删除该组合的当前持仓和已清仓历史；
- 删除操作不可恢复；
- 删除默认组合后，系统自动将排序第一的剩余组合设为默认；
- 删除最后一个组合后，允许系统暂时没有组合，并显示新建引导；
- 删除接口必须在后端执行所属关系校验和级联删除，不能只依赖前端。

#### 排序

- 支持用户手动调整组合顺序；
- 排序结果持久化到数据库；
- 页面刷新、重新登录后仍保持排序；
- 排序不改变组合内股票的任何数据。

#### 默认组合

- 同一用户同时只能有一个默认组合；
- 用户可以将任意组合设为默认；
- 默认组合在进入投资组合页面时自动打开；
- 默认标识只影响默认打开的组合，不影响组合汇总和排序。

### 6.4 组合详情头部

当前组合详情至少包含：

- 组合名称；
- 组合备注（可查看和编辑）；
- 默认组合标识；
- 当前持仓数量；
- 编辑组合、删除组合操作；
- 新增股票操作；
- 刷新行情操作；
- 当前市场状态和数据源状态。

### 6.5 组合汇总卡片

选中组合后展示以下动态指标：

| 指标 | 说明 |
|---|---|
| 当前持仓数 | 该组合状态为 `open` 的持仓记录数量 |
| 当前持仓市值 | 该组合有有效最新价的当前持仓市值之和；不包含现金余额 |
| 浮动盈亏 | 可计算持仓的总市值减去对应持仓成本 |
| 浮动盈亏率 | 浮动盈亏除以可计算持仓成本 |
| 已实现盈亏 | 已清仓记录中可计算清仓盈亏的合计 |
| 累计总盈亏 | 浮动盈亏与已实现盈亏之和；行情或历史清仓信息不完整时显示不完整状态 |

组合内股票行情发生变化时，汇总卡片同步刷新。

### 6.6 当前持仓与已清仓

组合详情继续提供两个页签：

- `当前持仓`：展示状态为 `open` 的持仓，并参与组合汇总和行情轮询；
- `已清仓`：展示状态为 `closed` 的历史记录，不参与组合汇总，不进行行情轮询。

页签数量只统计当前选中组合的数据，不统计其他组合。

### 6.7 组合内筛选

筛选条件只作用于当前选中的投资组合：

- 代码或名称关键词；
- 标的类型：全部、A 股、ETF；
- 建仓日期起止范围；
- 支持重置筛选条件。

筛选不会改变组合汇总的统计范围。组合汇总始终基于该组合全部当前持仓计算，而不是基于筛选后的股票列表。

## 7. 组合内股票管理

### 7.1 新增股票

新增股票必须在当前选中的投资组合下完成。

表单字段：

| 字段 | 必填 | 规则 |
|---|---:|---|
| 股票 / ETF | 是 | 必须从检索候选项中选择 |
| 平均持仓成本 | 是 | 非负数，最多 4 位小数 |
| 持股数量 | 是 | 新增时必须大于 0 的整数 |
| 建仓日期 | 是 | 默认当天，不得晚于当天 |
| 备注 | 否 | 纯文本，最多 1,000 个字符 |

标的检索规则：

1. 支持通过代码或名称检索。
2. 候选范围只包括 A 股和 ETF。
3. 用户必须从候选结果中选择有效标的后才能保存。
4. 选择后自动填充完整 `thscode`、代码、名称、类型和交易所。
5. 未重新选择候选项时，不允许使用手工输入内容保存。

### 7.2 持仓唯一性

1. 同一用户、同一 `thscode` 可以存在于多个投资组合中。
2. 同一投资组合内，同一 `thscode` 同时只能存在一条 `open` 当前持仓。
3. 已清仓记录不参与当前持仓唯一性判断。
4. 用户在同一组合重复新增当前持仓时，提示“该组合已有当前持仓，请编辑原记录”。
5. 同一股票再次建仓时，可以在原组合中新建新的当前持仓，但必须先使原记录进入 `closed`；也可以在其他组合中新建当前持仓。
6. 不支持多个批次持仓同时存在于同一组合内。

### 7.3 编辑股票

当前持仓允许编辑：

- 平均持仓成本；
- 持股数量；
- 建仓日期；
- 备注。

编辑时不允许替换股票或 ETF 身份。需要更换标的时，删除原记录后重新新增。

股票编辑不会改变其所属投资组合，也不支持通过编辑实现跨组合移动。

### 7.4 清仓

当用户将当前持仓数量修改为 0 并保存时：

1. 弹出清仓确认对话框；
2. 清仓确认区域展示清仓价格和清仓日期，清仓价格默认填充当前最新价；
3. 清仓价格和清仓日期必填，清仓日期不得晚于当天；
4. 确认后将状态改为 `closed`，保存清仓数量、清仓价格、清仓日期和操作时间；
5. 从当前持仓列表和当前持仓市值、浮动盈亏汇总中移除；
6. 在当前组合的“已清仓”页签中展示清仓金额、已实现盈亏和已实现盈亏率；
7. 已实现盈亏 = 清仓价格 × 清仓数量 - 平均成本 × 清仓数量；
8. 本版本暂不计算佣金、印花税等费用，也不维护现金余额。

已清仓记录可编辑备注和清仓信息，不能通过修改数量重新开仓。再次持有必须新增当前持仓。

### 7.5 删除股票

- 当前持仓和已清仓历史都支持永久删除；
- 删除前必须二次确认；
- 删除当前持仓后，组合汇总立即重新计算；
- 删除不影响组合本身；
- 如需保留历史，应优先使用清仓操作，而不是永久删除。

## 8. 组合动态计算规则

### 8.1 股票级计算

对于组合内每条当前持仓：

```text
持仓成本金额 = 平均持仓成本 × 持股数量
当前市值 = 最新价 × 持股数量
浮动盈亏 = 当前市值 - 持仓成本金额
浮动盈亏率 = 浮动盈亏 ÷ 持仓成本金额 × 100%
持仓占比 = 当前市值 ÷ 组合可计算总市值 × 100%
```

字段展示规则：

- 持仓成本金额为 0 时，浮动盈亏率显示“暂无数据”；
- 最新价缺失时，当前市值、浮动盈亏、浮动盈亏率和持仓占比均显示“暂无数据”；
- 缺失值不得用 0 替代；
- 当日涨跌幅使用当前数据源行情；
- 行情更新时间使用对应数据源返回时间；
- 当前持仓默认按用户保存的自定义顺序展示；支持对当前市值、浮动盈亏、盈亏率、组合占比和建仓日期进行临时排序，临时排序不改变保存顺序。

### 8.2 组合级计算

组合只统计状态为 `open` 的持仓。

```text
总成本 = 全部当前持仓的持仓成本金额之和
可计算持仓成本 = 有效最新价对应持仓的持仓成本金额之和
总市值 = 有效最新价对应持仓的当前市值之和
浮动盈亏 = 总市值 - 可计算持仓成本
浮动盈亏率 = 浮动盈亏 ÷ 可计算持仓成本 × 100%
已实现盈亏 = Σ(清仓价格 - 平均成本) × 清仓数量
累计总盈亏 = 浮动盈亏 + 已实现盈亏
```

规则：

1. 总成本统计全部当前持仓，即使行情缺失。
2. 总市值、浮动盈亏和浮动盈亏率只统计有有效最新价的持仓。
3. 可计算持仓成本为 0 时，浮动盈亏率显示“暂无数据”。
4. 没有当前持仓时，组合汇总显示空状态或 0，不能发起不必要的行情请求。
5. 只要有一条当前持仓缺少有效行情，组合标记为“数据不完整”。
6. 组合汇总不受当前筛选条件影响。
7. 已清仓记录不参与任何当前组合汇总。
8. 已实现盈亏只统计同时具备清仓价格和清仓数量的已清仓记录；部分记录缺失时标记为“不完整”。
9. 当前持仓市值不包含现金余额，不能作为包含现金的组合总资产。

### 8.3 行情缺失

当部分股票缺少最新行情时：

- 总成本仍正常展示；
- 总市值、浮动盈亏和浮动盈亏率按可计算持仓汇总；
- 组合汇总区域显示“部分持仓行情缺失，汇总数据不完整”；
- 对应股票显示“暂无数据”；
- 不将缺失行情当作 0；
- 页面保留最后成功行情时，必须明确标记为“最后成功行情”或等价状态。

## 9. 行情刷新

沿用现有数据源、市场状态和行情缓存机制。

1. 当前组合的 A 股行情尽量批量查询。
2. ETF 按数据源能力批量或逐只查询，并由后端缓存。
3. 交易时段约每 5 秒刷新当前组合的最新价、当日涨跌幅和派生指标。
4. 非交易时段不持续轮询。
5. 已清仓页签不轮询行情。
6. 手动点击“刷新行情”时立即重新请求当前组合数据。
7. 编辑组合或编辑股票时，行情刷新不得覆盖用户输入。
8. 同一股票出现在多个组合时，后端可以复用行情缓存，但必须按各自组合的数量和成本分别计算。
9. 当前组合切换后，应加载新组合的行情上下文和汇总。
10. 投资组合页面之外的页面不因本次需求新增轮询。

## 10. 数据模型建议

### 10.1 `portfolios`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `user_id` | UUID | 所属用户 |
| `name` | VARCHAR(50) | 组合名称 |
| `note` | TEXT | 组合备注，可为空 |
| `is_default` | BOOLEAN | 是否为默认组合；同一用户最多一个 |
| `sort_order` | INTEGER | 用户自定义排序值 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 修改时间 |

### 10.2 组合与持仓关系

现有持仓记录增加 `portfolio_id` 外键，关系变为：

```text
portfolios 1 ──── N holdings
```

要求：

- `portfolio_id` 非空；
- 组合删除时级联删除持仓记录；
- 持仓仍保留原有 `open` / `closed` 状态；
- 将当前唯一性索引从 `(user_id, thscode)` 调整为 `(portfolio_id, thscode)`，且只约束 `status = 'open'`；
- 用户隔离仍通过 `user_id` 校验，不能仅依赖 `portfolio_id`。

### 10.3 持仓字段保留

现有持仓字段继续保留：

- `thscode`；
- `ticker`；
- `name`；
- `asset_type`；
- `exchange`；
- `average_cost`；
- `quantity`；
- `opened_on`；
- `note`；
- `status`；
- `closed_quantity`；
- `close_price`；
- `closed_on`；
- `closed_at`；
- `created_at`；
- `updated_at`。

本次不增加交易流水、现金、目标权重或历史净值字段；`close_amount`、`realized_gain` 和 `realized_gain_percent` 为接口动态计算字段，不单独持久化。

## 11. 既有数据迁移

### 11.1 迁移目标

既有用户的当前持仓和已清仓历史必须迁移到默认投资组合，不丢失记录内容。

### 11.2 迁移规则

1. 为每个既有用户创建一个默认组合，名称为“我的投资组合”。
2. 即使用户没有持仓，也创建该默认空组合，保证页面首次进入有明确默认对象。
3. 将该用户全部现有持仓记录的 `portfolio_id` 设置为该默认组合 ID。
4. 保留持仓原有 ID、标的字段、平均成本、数量、建仓日期、备注、状态、清仓时间、创建时间和更新时间。
5. 当前持仓和已清仓历史都归入默认组合。
6. 迁移完成后，旧的用户级当前持仓唯一性约束改为组合级唯一性约束。
7. 迁移必须支持事务回滚，不能产生没有所属组合的持仓记录。
8. 迁移完成后，用户可以新建其他组合；不支持在迁移过程中自动拆分持仓。

### 11.3 新用户默认组合

新用户第一次进入投资组合功能时，如果没有投资组合，系统创建“我的投资组合”作为默认空组合。

## 12. 接口需求

以下接口为推荐的业务边界，具体命名可按项目现有接口风格实现。

### 12.1 投资组合

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/portfolios` | 获取当前用户的组合列表及排序信息 |
| `POST` | `/api/portfolios` | 新建组合 |
| `GET` | `/api/portfolios/{portfolio_id}` | 获取组合详情 |
| `PATCH` | `/api/portfolios/{portfolio_id}` | 修改名称或备注 |
| `DELETE` | `/api/portfolios/{portfolio_id}` | 删除组合并级联删除持仓 |
| `POST` | `/api/portfolios/{portfolio_id}/default` | 设置默认组合 |
| `PATCH` | `/api/portfolios/order` | 保存组合排序 |

组合接口返回的数据至少应支持前端展示：

- 组合 ID；
- 名称；
- 备注；
- 默认标识；
- 排序值；
- 当前持仓数量；
- 创建和更新时间。

### 12.2 组合汇总与持仓

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/portfolios/{portfolio_id}/summary` | 获取当前组合动态汇总和行情上下文 |
| `GET` | `/api/portfolios/{portfolio_id}/holdings?status=open` | 获取当前持仓 |
| `GET` | `/api/portfolios/{portfolio_id}/holdings?status=closed` | 获取已清仓历史 |
| `POST` | `/api/portfolios/{portfolio_id}/holdings` | 在指定组合中新增持仓 |
| `PATCH` | `/api/portfolios/{portfolio_id}/holdings/{holding_id}` | 修改组合内持仓 |
| `DELETE` | `/api/portfolios/{portfolio_id}/holdings/{holding_id}` | 删除组合内持仓 |

接口必须校验：

- `portfolio_id` 属于当前用户；
- `holding_id` 属于指定 `portfolio_id`；
- 新增股票的标的来自有效检索结果；
- 当前组合内不存在同标的的其他 `open` 记录。

### 12.3 标的检索

现有标的检索能力继续复用，仍支持：

```text
GET /api/instruments/search?q=...
```

检索范围继续限定为 A 股和 ETF。

## 13. 错误与边界

1. 未选择有效组合时，不能新增组合内股票。
2. 组合名称为空时不能保存。
3. 组合内重复新增同一当前标的时返回明确冲突提示。
4. 修改不存在或不属于当前用户的组合时返回 404。
5. 使用其他用户的组合 ID 访问持仓时不得泄露数据。
6. 删除组合时，即使组合为空也必须完成正常删除。
7. 删除默认组合后应重新选择默认组合；若无剩余组合则允许为空。
8. 已清仓记录不得通过数量修改重新打开。
9. 持仓数量改为 0 时必须经过清仓确认。
10. 清仓确认必须提供清仓价格和清仓日期；已有历史记录缺少相关字段时显示“暂无数据”，不能伪造清仓盈亏。
10. 最新行情缺失时不得返回伪造的 0 市值或 0 盈亏。
11. 数据源未配置时，组合和本地持仓数据仍可访问，行情字段显示不可用状态。
12. 数据源不可用时，保留最后成功行情并明确标记过期；没有历史行情时显示缺失状态。
13. 筛选条件传入起止日期倒置时，沿用现有容错逻辑或给出明确校验提示，但不能影响其他组合数据。
14. 组合删除和数据迁移必须使用数据库事务，不能留下孤儿持仓。

## 14. 验收标准

### 14.1 组合管理

1. 导航和页面名称显示为“投资组合”。
2. 用户可以新建、编辑和删除投资组合。
3. 用户可以创建空组合。
4. 用户可以调整组合顺序，刷新后顺序保持不变。
5. 用户可以设置默认组合，重新进入页面时自动选中默认组合。
6. 删除组合前有二次确认。
7. 删除组合后，其当前持仓和已清仓历史同时删除。
8. 删除默认组合后，默认组合状态正确处理。

### 14.2 页面交互

1. 页面采用组合列表和选中组合详情布局。
2. 切换组合后，汇总、当前持仓、已清仓和筛选结果均切换为目标组合的数据。
3. 空组合显示添加股票引导。
4. 组合内新增股票只能添加到当前选中的组合。
5. 组合备注和股票备注可以分别编辑。
6. 本次改动不改变总览页面展示。

### 14.3 股票持仓

1. 支持检索并选择 A 股和 ETF。
2. 同一股票可以出现在多个组合中。
3. 同一组合内不能存在两条相同标的的当前持仓。
4. 可以编辑平均成本、数量、建仓日期和备注。
5. 编辑时不能替换标的身份。
6. 数量改为 0 后必须确认清仓，并进入当前组合的已清仓页签。
7. 清仓记录保存清仓数量、清仓价格、清仓日期，并展示清仓金额、已实现盈亏和已实现盈亏率。
8. 已清仓记录可以补录清仓信息，但不能通过修改数量重新开仓。
9. 股票在不同组合间不支持移动。

### 14.4 动态汇总

1. 组合总成本按当前组合全部 `open` 持仓计算。
2. 组合总市值按有效最新价计算。
3. 组合浮动盈亏和浮动盈亏率计算正确。
4. 每只股票的当前市值、盈亏、盈亏率和持仓占比计算正确。
5. 已实现盈亏和累计总盈亏计算正确；当前持仓市值不包含现金余额。
5. 同一股票在不同组合中时，各组合按自身数量和成本独立计算。
6. 行情缺失时显示“暂无数据”，不使用 0 替代。
7. 部分行情缺失时显示组合汇总不完整提示。
8. 行情刷新不会覆盖编辑表单中的用户输入。
9. 交易时段当前组合约每 5 秒刷新行情，非交易时段不持续轮询。
10. 已清仓页签不进行行情轮询。

### 14.5 数据迁移与隔离

1. 既有用户自动获得“我的投资组合”默认组合。
2. 既有当前持仓和已清仓历史全部迁移到该组合。
3. 迁移前后持仓关键字段和记录 ID 不丢失。
4. 迁移后旧的全局同标的限制变为组合内同标的限制。
5. 用户 A 无法访问、修改或删除用户 B 的组合和持仓。
6. 组合删除不会留下孤儿持仓记录。

### 14.6 明确不验收

以下内容不属于本次版本验收范围：

- 收益曲线；
- 组合历史净值；
- 资金流水；
- 交易流水；
- 调仓分析；
- 目标持仓比例；
- 自动调仓建议；
- 佣金、印花税等交易费用；
- 现金余额和资金流水；
- 总览页面组合卡片。

## 15. 后续扩展预留

本次不实现收益曲线、历史净值和调仓分析，但数据模型和接口命名不应阻碍后续扩展。

后续若需要准确收益核算，应新增：

- 买入、卖出和资金进出事件；
- 组合现金或净投入资金；
- 每日组合资产快照；
- 分红、费用等影响记录。

后续若需要调仓分析，应新增：

- 每只股票的目标持仓比例；
- 当前占比与目标占比的偏离计算；
- 可选的调仓阈值；
- 如需计算买卖数量，还需要现金和交易规则。
