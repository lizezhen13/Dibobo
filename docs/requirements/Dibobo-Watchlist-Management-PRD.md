# Dibobo 自选管理功能 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 功能名称 | 自选管理 |
| 文档版本 | V1.0 |
| 需求状态 | 已确认，可进入开发 |
| 确认日期 | 2026-08-09 |
| 适用端 | Web |
| 数据范围 | A 股、ETF |
| 数据归属 | 当前登录用户 |
| 相关功能 | 投资组合、数据源设置、行情数据 |

> 本文档记录已确认的产品需求。自选管理仅用于添加和观察用户关注的股票/ETF，不涉及交易、持仓或投资组合管理。

## 2. 产品目标

为用户提供一个简单、持久化的自选列表，使用户可以：

1. 通过股票名称或代码快速搜索 A 股和 ETF；
2. 将关注标的添加到自己的自选列表；
3. 查看关注标的的实时行情和基础信息；
4. 自定义列表顺序，并按行情字段临时排序；
5. 编辑备注、删除单只或批量删除自选标的。

## 3. 范围定义

### 3.1 本次包含

- 单一自选股票列表；
- A 股和 ETF 的搜索与添加；
- 自选标的数据库持久化；
- 单只删除和批量删除；
- 自定义拖拽排序；
- 关键词搜索和标的类型筛选；
- 表头临时排序；
- 备注新增和编辑；
- 交易时段行情自动刷新；
- 行情缺失、刷新失败和最后成功行情展示。

### 3.2 本次不包含

- 自选分组；
- 普通基金；
- 指数；
- 股票详情页；
- 价格提醒或涨跌提醒；
- 导入和导出；
- 分享、协作和多人编辑；
- 与投资组合的联动；
- 买入、卖出、交易记录；
- 成本、持仓数量、市值、盈亏等投资组合字段；
- 市盈率、市净率、总市值等额外估值字段。

## 4. 用户与数据权限

1. 用户必须登录后才能访问自选管理。
2. 自选数据属于当前登录用户。
3. 用户只能读取、添加、修改和删除自己的自选记录。
4. 不同用户之间的自选列表完全隔离。
5. 自选数据保存到数据库，不使用浏览器本地存储作为唯一数据源。
6. 同一用户、同一标的只能存在一条自选记录。

## 5. 标的范围

### 5.1 支持范围

支持以下两类标的：

| 标的类型 | 标识 | 交易所范围 |
|---|---|---|
| A 股 | `a_share` | 沪市、深市、北交所 |
| ETF | `fund_etf` | 由当前数据源支持的交易所 |

### 5.2 不支持范围

- 普通开放式基金；
- 指数；
- 非 A 股股票；
- 数据源无法识别的标的。

搜索候选项只能返回支持范围内的标的，用户不能通过手工输入未被候选项识别的代码完成添加。

## 6. 页面入口与整体布局

### 6.1 页面入口

- 使用现有导航中的“自选管理”入口；
- 替换当前占位页面；
- 推荐路由继续使用现有自选管理路由，不新增分组路由。

### 6.2 页面结构

页面由以下区域组成：

1. 页面标题区：标题“自选管理”和功能说明；
2. 操作区：添加自选、关键词筛选、类型筛选、刷新行情、批量删除；
3. 自选列表区：使用表格展示标的和行情；
4. 空状态区：没有任何自选时，引导用户搜索并添加；
5. 加载、错误和行情状态提示区。

页面不显示分组侧栏、组合卡片或多列表切换控件。

## 7. 添加自选

### 7.1 搜索方式

提供一个输入框，支持按以下内容搜索：

- 股票名称；
- 股票代码；
- ETF 名称；
- ETF 代码。

搜索结果必须经过候选项选择后才能添加。

### 7.2 搜索结果

候选结果至少展示：

- 标的名称；
- 标的代码；
- 标的类型（A 股/ETF）。

搜索结果只包含 A 股和 ETF，不展示普通基金、指数及其他资产类型。

### 7.3 添加流程

1. 用户在搜索框输入名称或代码；
2. 系统加载匹配的候选标的；
3. 用户选择一个候选项；
4. 用户点击“添加”完成添加；
5. 添加成功后列表立即刷新，并将新标的放置在默认顺序的顶部；
6. 搜索框和已选择状态在添加成功后清理。

用户不能直接保存未经候选项确认的手工输入内容。

### 7.4 重复添加

当用户添加同一标的时：

- 后端以当前用户和 `thscode` 作为唯一性判断；
- 添加被拒绝；
- 页面提示“该标的已在自选列表”；
- 不创建重复记录；
- 原有备注、排序和添加时间不被覆盖。

## 8. 自选列表字段

### 8.1 展示字段

| 字段 | 说明 | 数据来源/规则 |
|---|---|---|
| 股票代码 | 展示标的代码 | 标的基础信息 |
| 股票名称 | 展示标的名称 | 标的基础信息 |
| 最新价 | 当前最新成交价 | 实时行情 |
| 涨跌额 | 相对前一交易日收盘价的涨跌金额 | 行情数据或由最新价与昨收价计算 |
| 涨跌幅 | 当日涨跌百分比 | 实时行情 |
| 成交量 | 当日成交量 | 实时行情 |
| 成交额 | 当日成交金额 | 实时行情 |
| 行业 | A 股所属行业 | 标的基础信息 |
| 添加时间 | 用户添加该标的的时间 | 自选记录创建时间 |
| 备注 | 用户自定义观察说明 | 自选记录，可编辑 |

### 8.2 字段展示规则

1. 行情数值沿用现有行情页面的格式化和精度规则。
2. 成交量和成交额沿用现有数据源的单位转换规则；若系统尚无统一规则，应采用易读的万/亿单位展示。
3. ETF 没有适用行业时，行业显示“—”。
4. 基础信息或行情缺失时显示“—”或“暂无数据”，不得用 0 伪造数据。
5. 股票名称或基础信息发生变化时，列表使用数据源返回的最新信息。
6. 添加时间由系统自动记录，用户不可修改。
7. 用户只能编辑备注，不能在自选列表中修改标的身份。

### 8.3 备注

- 备注为可选字段；
- 添加时可以填写；
- 添加后可以编辑；
- 纯文本；
- 最长 1,000 个字符；
- 备注为空时不展示占位文本以外的内容。

## 9. 删除自选

### 9.1 删除单只标的

1. 每行提供删除操作；
2. 用户点击删除后弹出二次确认；
3. 确认内容应包含标的名称和代码；
4. 确认后永久删除该自选记录；
5. 删除成功后列表和自定义顺序立即更新；
6. 取消则不产生任何数据变化。

### 9.2 批量删除

1. 每行提供复选框；
2. 支持全选当前筛选结果；
3. 未选择任何记录时，批量删除按钮不可用；
4. 点击批量删除后弹出二次确认；
5. 确认后删除选中的全部自选记录；
6. 删除成功后清空选择状态并刷新列表；
7. 批量删除不影响未被选中的自选记录。

## 10. 排序、筛选与拖拽

### 10.1 自定义拖拽排序

1. 用户可以通过拖拽调整自选列表顺序；
2. 自定义顺序保存到数据库；
3. 页面重新进入后恢复最近一次保存的顺序；
4. 首次添加的标的默认位于列表顶部；
5. 拖拽只在“自定义排序”状态下启用；
6. 关键词筛选、类型筛选或表头临时排序生效时，暂不允许拖拽；
7. 退出临时排序后恢复自定义顺序；
8. 删除记录后，剩余记录的顺序自动补齐。

### 10.2 表头临时排序

支持点击表头对以下字段进行升序/降序临时排序：

- 股票代码；
- 股票名称；
- 最新价；
- 涨跌额；
- 涨跌幅；
- 成交量；
- 成交额；
- 行业；
- 添加时间。

临时排序只影响当前页面展示，不覆盖数据库中的自定义顺序。刷新页面或切回自定义排序后，恢复自定义顺序。

### 10.3 关键词筛选

关键词筛选匹配：

- 股票代码；
- 股票名称。

关键词为空时展示全部自选记录。

### 10.4 类型筛选

类型筛选选项：

- 全部；
- A 股；
- ETF。

筛选只影响列表展示，不影响数据库数据，也不影响用户自定义顺序的保存。

## 11. 行情刷新

### 11.1 刷新原则

自选管理沿用投资组合现有行情刷新机制、数据源、市场状态判断和缓存机制。

1. 交易时段自动刷新当前自选列表行情；
2. 刷新频率使用现有数据源返回的 `refresh_seconds`，默认约 5 秒；
3. 支持点击“刷新行情”立即刷新；
4. 浏览器页面隐藏时暂停自动轮询；
5. 页面重新获得焦点时重新请求行情；
6. 非交易时段不持续轮询；
7. 只刷新当前自选管理页面，不因本功能给其他页面增加轮询；
8. 添加、删除、编辑备注和调整顺序不会被行情刷新覆盖。

### 11.2 刷新范围

自动刷新只更新动态行情字段：

- 最新价；
- 涨跌额；
- 涨跌幅；
- 成交量；
- 成交额。

以下字段不因行情轮询改变：

- 股票代码；
- 股票名称；
- 行业；
- 添加时间；
- 备注；
- 自定义排序。

### 11.3 行情缺失和刷新失败

1. 股票没有可用行情时，仍保留在自选列表；
2. 从未成功获取行情时，动态字段显示“暂无数据”；
3. 已有成功行情但本次刷新失败时，保留最后一次成功行情；
4. 页面明确标记“最后成功行情”或等价状态；
5. 不将行情缺失当作 0；
6. 单只股票行情失败不应阻断其他股票更新；
7. 数据源不可用时，保留列表和基础信息，并展示数据源错误提示及重试入口。

### 11.4 停牌和退市

- 停牌标的继续保留；
- 暂时无法返回行情的标的显示“暂无数据”；
- 退市或数据源暂时无法识别的标的不自动删除；
- 用户仍可手动删除该标的。

## 12. 页面状态与提示

### 12.1 空状态

没有任何自选时：

- 展示空列表插图或空状态文案；
- 提示“还没有自选股票”；
- 提供搜索添加入口。

### 12.2 加载状态

- 首次加载显示列表骨架屏或加载状态；
- 搜索候选加载时显示加载提示；
- 刷新行情时保留已有列表内容，并仅对动态字段显示刷新状态；
- 添加、删除、保存备注、保存排序时禁用对应操作，避免重复提交。

### 12.3 错误提示

至少覆盖以下场景：

| 场景 | 页面行为 |
|---|---|
| 搜索无结果 | 提示未找到匹配标的 |
| 添加重复标的 | 提示该标的已在自选列表 |
| 添加失败 | 保留当前输入并提示失败原因 |
| 删除失败 | 保留列表并提示可重试 |
| 备注保存失败 | 保留编辑内容并提示可重试 |
| 排序保存失败 | 提示失败，并恢复最近一次成功顺序 |
| 行情获取失败 | 保留列表，显示暂无数据或最后成功行情 |
| 未登录或会话失效 | 按现有认证机制处理 |

## 13. 数据模型建议

建议新增 `watchlist_items` 表，每个用户对应一个无分组的自选列表。

### 13.1 `watchlist_items`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | UUID | 是 | 主键 |
| `user_id` | UUID | 是 | 所属用户 |
| `thscode` | VARCHAR(20) | 是 | 数据源统一标的代码 |
| `ticker` | VARCHAR(20) | 是 | 展示代码 |
| `name` | VARCHAR(100) | 是 | 标的名称快照 |
| `asset_type` | VARCHAR(20) | 是 | `a_share` 或 `fund_etf` |
| `exchange` | VARCHAR(10) | 是 | `SH`、`SZ`、`BJ` 或数据源支持的 ETF 交易所 |
| `industry` | VARCHAR(100) | 否 | 行业；ETF 可为空 |
| `note` | TEXT | 否 | 用户备注，最多 1,000 字符 |
| `sort_order` | INTEGER | 是 | 用户自定义顺序 |
| `added_at` | TIMESTAMP | 是 | 添加时间 |
| `created_at` | TIMESTAMP | 是 | 记录创建时间 |
| `updated_at` | TIMESTAMP | 是 | 记录更新时间 |

### 13.2 数据约束

1. 建立 `(user_id, thscode)` 唯一约束；
2. `user_id` 关联当前用户，并建立索引；
3. `sort_order` 按用户独立维护；
4. 删除用户时级联删除该用户的自选记录；
5. 不设置分组字段；
6. 不将最新行情直接作为自选记录的持久化字段，行情应通过现有行情数据源和缓存动态获取；
7. 股票名称、代码、行业等基础信息允许在数据源变化后更新。

## 14. 接口建议

接口应遵循现有认证、CSRF、防用户越权和数据源错误处理规范。

### 14.1 自选列表

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/watchlist` | 获取当前用户的自选列表及行情 |
| `POST` | `/api/watchlist` | 添加一条自选记录 |
| `PATCH` | `/api/watchlist/{item_id}` | 修改备注 |
| `DELETE` | `/api/watchlist/{item_id}` | 删除一条自选记录 |
| `PATCH` | `/api/watchlist/order` | 保存自定义排序 |
| `POST` | `/api/watchlist/batch-delete` | 批量删除自选记录 |

### 14.2 列表查询参数

`GET /api/watchlist` 支持：

- `keyword`：按代码或名称筛选；
- `asset_type`：`a_share`、`fund_etf`；
- 可选的服务端排序参数，但临时排序不得修改 `sort_order`。

### 14.3 标的搜索

沿用现有标的搜索能力，并限制候选范围：

`GET /api/instruments/search?q={query}&asset_type=a_share,fund_etf`

服务端必须再次校验标的类型，不能仅依赖前端筛选。

### 14.4 行情响应上下文

自选列表接口应返回与投资组合一致的行情上下文，至少包括：

- 数据源状态；
- 市场状态；
- 是否启用轮询；
- 刷新间隔；
- 是否使用最后成功行情；
- 每条记录的行情时间或缺失状态。

这些状态用于页面刷新控制和异常提示，不额外作为主要表格字段展示。

## 16. 验收标准

### 16.1 添加与搜索

- [ ] 可以按股票名称搜索 A 股和 ETF；
- [ ] 可以按股票代码搜索 A 股和 ETF；
- [ ] 搜索结果不包含普通基金和指数；
- [ ] 必须选择候选项后才能添加；
- [ ] 添加成功后记录保存到数据库；
- [ ] 重复添加被阻止并显示明确提示；
- [ ] 首次添加的标的位于列表顶部。

### 16.2 列表与字段

- [ ] 列表展示代码、名称、最新价、涨跌额、涨跌幅、成交量、成交额、行业、添加时间和备注；
- [ ] ETF 行业显示“—”；
- [ ] 行情缺失显示“暂无数据”或“—”，不显示伪造的 0；
- [ ] 备注可以添加和编辑；
- [ ] 添加时间由系统生成且不可编辑。

### 16.3 排序与筛选

- [ ] 可以拖拽调整自定义顺序；
- [ ] 刷新页面后自定义顺序保持不变；
- [ ] 可以按价格、涨跌幅、添加时间等表头临时排序；
- [ ] 临时排序不会覆盖自定义顺序；
- [ ] 可以按代码或名称关键词筛选；
- [ ] 可以按全部、A 股、ETF 筛选；
- [ ] 筛选后可以全选当前筛选结果并批量删除。

### 16.4 删除与权限

- [ ] 单只删除需要二次确认；
- [ ] 批量删除需要二次确认；
- [ ] 删除后列表和顺序立即更新；
- [ ] 用户无法读取或操作其他用户的自选记录；
- [ ] 删除不会影响投资组合或其他业务数据。

### 16.5 行情刷新

- [ ] 交易时段按投资组合现有刷新机制自动刷新；
- [ ] 支持手动刷新行情；
- [ ] 页面隐藏时暂停自动轮询；
- [ ] 非交易时段不持续轮询；
- [ ] 行情刷新不会覆盖备注、排序和基础信息；

- [ ] 一只股票行情失败不会阻断其他标的更新。
