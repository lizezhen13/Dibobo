# Dibobo 事件日历 V1 PRD

| 文档属性 | 内容 |
|---|---|
| 产品 | Dibobo |
| 功能 | 事件日历（Event Calendar） |
| 版本 | V1.0 |
| 文档状态 | 开发与联调稿 |
| 目标终端 | PC Web |
| 默认时区 | Asia/Shanghai（北京时间，GMT+08:00） |
| 主要数据源 | Longbridge OpenAPI |

> 本文档覆盖原有事件日历 PRD。本文档中的产品范围、交互和验收标准以本版本为准；旧 PRD 中未在本文档保留的政策、突发新闻、多数据源合并、IPO 和事件状态等内容不属于 V1。

## 1. 背景与目标

### 1.1 背景

Dibobo 需要提供一个统一的事件日历入口，帮助用户按日期查看可能影响投资决策的关键事件：

- 宏观经济数据发布时间；
- 自选股和投资组合持仓股票的财报、分红、拆股/合股；
- US、HK、CN 等市场的休市和半日市安排。

Longbridge 已接入 Dibobo，并提供财经日历相关数据。扶摇继续承担现有行情及业务接口；Longbridge 仅作为事件日历的数据源，两者并存运行，前端不直接访问 Longbridge。

### 1.2 产品目标

1. 用一个月历视图展示事件分布。
2. 用右侧时间线按日期和时间连续展示事件。
3. 让宏观数据、股票事件和休市事件使用适合自身语义的卡片信息。
4. 自动聚合当前用户的自选股和所有投资组合中的当前持仓股票。
5. 支持查看当前日期、未来日期和历史月份。
6. 在缺失字段或数据源异常时保持页面可用，不伪造数据。

### 1.3 非目标

V1 不包含以下能力：

- 政策文件、监管文件和突发新闻事件；
- IPO 日历；
- 股东会议；
- 邮件、短信、浏览器推送或其他事件提醒；
- 事件的“已发布”“已完成”“已确认”等用户可见状态；
- 自动判断利好/利空或生成投资建议；
- 自动下单；
- 多数据源冲突合并；
- SG 市场事件；
- 展示非自选、非当前持仓股票的公司事件。

## 2. 数据范围

### 2.1 V1 事件分类

顶部分类标签固定为：

| UI 标签 | 内部类别 | Longbridge 数据类别 | 说明 |
|---|---|---|---|
| 经济数据 | `macro` | `macrodata` | CPI、GDP、PMI、非农、利率决议等宏观数据发布 |
| 财报 | `earnings` | `report` | 自选股和当前持仓股票的财报事件 |
| 分红 | `dividend` | `dividend` | 除息日、派息日和分红金额等 |
| 拆合 | `split` | `split` | 拆股、合股/反向拆股及比例等 |
| 休市 | `closed` | `closed` / 交易日历 | 市场休市和半日市 |

Longbridge 还支持 IPO 等其他财经日历类别，但 V1 不展示。[Longbridge 财经日历命令说明](https://open.longbridge.com/docs/cli/fundamentals/finance-calendar)

### 2.2 市场范围

财经事件查询支持以下市场：

- US；
- HK；
- SH；
- SZ。

休市日历支持以下市场：

- US；
- HK；
- CN。

不支持 SG。`CN` 作为大陆市场整体休市/交易日历标识；证券事件继续使用 Longbridge 返回的 `SH`、`SZ` 市场标识。

Longbridge SDK 层支持按 `start`、`end` 和 `market` 查询；HTTP 适配器实际发送 `date`、`date_end`、`types[]` 和 `markets[]` 参数，响应按日期分组并通过 `next_date` 分页。[宏观日历接口](https://open.longbridge.com/docs/market/calendar/macro-calendar)、[分红日历接口](https://open.longbridge.com/docs/market/calendar/dividend-calendar)

### 2.3 股票范围

股票事件的证券集合由 Dibobo 本地数据计算，不直接使用 Longbridge 账户的自选股或持仓列表：

1. 查询当前用户的自选股；
2. 查询当前用户所有投资组合中的 `open` 持仓；
3. 使用标准化证券标识合并两组股票；
4. 查询这些股票的财报、分红和拆合事件；
5. 为事件附加 `watchlist`、`holding` 来源标签。

同一股票同时出现在自选股和多个投资组合中，只展示一条事件。股票事件不能仅通过公司简称匹配，至少应优先使用代码和市场匹配。

### 2.4 历史与未来

- 默认进入当前月份；
- 支持切换到历史月份；
- 支持查看 Longbridge 返回范围内的已发生和未发生事件；
- 历史事件不添加“历史”“已完成”等状态标签；
- 如果 Longbridge 返回实际值，则直接展示实际值；
- 未来事件不显示“预计”状态标签，只展示日期、时间和可用数据。

## 3. 页面信息架构

### 3.1 页面路由

```text
/calendar
```

### 3.2 页面整体布局

页面参考用户提供的日历截图，采用左右双栏结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 经济数据  财报  分红  拆合  休市                 当前时间  筛选 │
├─────────────────────────────────┬────────────────────────────┤
│ 左侧：月历                       │ 右侧：事件时间线            │
│ 今天 / 上月 / 月份 / 下月         │ 从选中日期开始，按时间排序     │
│ 星期和日期网格                    │ 日期分组 + 事件卡片           │
└─────────────────────────────────┴────────────────────────────┘
```

建议初始比例：左侧约 2/3，右侧约 1/3。右侧时间线独立滚动，月历保持可见。

### 3.3 顶部分类标签

- 五个标签单选；
- 点击标签后，月历和右侧时间线同步切换；
- 默认选中“经济数据”；
- 不提供“全部”标签；
- 当前标签使用高对比度选中态；
- “新股/IPO”不出现在正式页面。

### 3.4 顶部日期控制

从左到右包含：

1. “今天”按钮；
2. 上一个月按钮；
3. 当前年月标题；
4. 下一个月按钮；
5. 当前北京时间展示，例如 `当前时间：17:20 (GMT+08:00)`；
6. 筛选按钮。

交互规则：

- 点击“今天”将月份和选中日期恢复为当前北京时间日期；
- 点击上月/下月切换月份；
- 切换月份后默认选中该月 1 日；
- 点击月历中的日期后，该日期高亮，并成为右侧时间线的起始日期。

## 4. 月历视图

### 4.1 月历基础规则

- 一周从星期日开始，展示日、一、二、三、四、五、六；
- 展示当前月份完整日期网格，必要时包含相邻月份的补充日期；
- 当前选中日期使用背景色或边框高亮；
- 今天在非选中状态下仍保留清晰的日期标识；
- 日期按北京时间归属。

### 4.2 日期单元格事件展示

- 单元格内最多展示 2 条事件标签；
- 超出 2 条时显示 `+N`；
- 无事件的日期保持空白，不显示“暂无事件”；
- 事件标签按当天排序：全天事件优先，具体时间事件按时间升序；
- 标签颜色按事件类型区分，不以颜色单独表达重要性；
- 点击事件标签打开右侧详情抽屉；
- 点击日期空白区域只改变选中日期，不打开详情。

### 4.3 月历标签内容

月历标签使用紧凑形式，不展示完整数据指标：

| 事件类型 | 标签建议 |
|---|---|
| 经济数据 | 国家/地区图标 + 指标简称 |
| 财报 | 股票代码或简称 + 财报 |
| 分红 | 股票代码或简称 + 分红 |
| 拆合 | 股票代码或简称 + 拆合 |
| 休市 | 市场图标 + 休市名称 |

## 5. 右侧事件时间线

### 5.1 时间线范围

- 初次进入时从今天开始；
- 用户切换月份后从该月 1 日开始；
- 用户点击日期后从选中日期开始；
- 可跨越当前月份继续展示后续日期；
- 查看历史日期时，从历史选中日期开始按时间升序展示；
- 不因为历史/未来而增加事件状态标签。

### 5.2 时间线排序

排序优先级：

1. 事件日期升序；
2. 同一天内，全天事件优先；
3. 有具体时间的事件按时间升序；
4. 时间相同则重要性高的事件优先；
5. 仍相同则保持 Longbridge 返回顺序。

### 5.3 时间线分组

每个日期组包含：

- 完整日期，例如 `2026 年 8 月 31 日 星期一`；
- 该日期下的事件卡片列表。

右侧列表首屏加载一批事件，继续滚动或点击“加载更多”后按相同筛选条件加载后续数据。具体分页大小由后端接口确定，但前端不得一次性渲染无限事件。

### 5.4 无结果规则

- 月历没有事件的日期保持空白；
- 右侧时间线没有任何结果时，显示列表级空状态，例如“当前范围暂无事件”；
- 空状态不影响月份切换、分类切换和筛选操作。

## 6. 事件卡片规范

事件卡片使用统一容器、边框、圆角和点击行为，但根据事件类型展示不同字段。不得使用一个包含大量空字段的通用卡片。

### 6.1 经济数据卡片

展示字段：

- 国家/地区图标；
- 国家/地区名称；
- 指标名称；
- 数据所属期间；
- 北京时间或“全日”；
- 重要性标识；
- 实际值、预测值、前值（数据存在时）。

示例：

```text
🇺🇸 美国
CPI · 2026 年 7 月
08 月 12 日 20:30       ★★★
前值 2.7%    预测 2.8%
```

经济数据卡片不显示股票名称、股票代码、自选标签或持仓标签。

### 6.2 财报卡片

展示字段：

- 股票名称；
- 股票代码和市场；
- 财报类型或报告期；
- 北京时间或“全日”；
- 盘前/盘后/盘中信息（数据存在时）；
- “自选”“持仓”来源标签；
- EPS、营收实际值/预测值（数据存在时）。

### 6.3 分红卡片

展示字段：

- 股票名称；
- 股票代码和市场；
- 事件日期；
- 除息日、派息日等具体日期（数据存在时）；
- 分红金额和币种（数据存在时）；
- “自选”“持仓”来源标签。

### 6.4 拆合卡片

展示字段：

- 股票名称；
- 股票代码和市场；
- 拆股、合股或反向拆股类型；
- 比例（数据存在时）；
- 生效日期；
- “自选”“持仓”来源标签。

Longbridge 的拆股日历覆盖拆股和反向拆股，CLI 日历说明同时包含拆股与合股事件。[拆股日历接口](https://open.longbridge.com/docs/market/calendar/split-calendar)

### 6.5 休市卡片

展示字段：

- 市场图标；
- 市场名称；
- 休市名称或 Longbridge 返回的内容；
- 日期；
- `全日` 或 `半日市`。

休市卡片不显示重要性、不显示股票字段、不显示自选/持仓标签。

如果数据源没有返回节假日名称，只显示“市场休市”，不得自行编造节日名称。

## 7. 详情抽屉

### 7.1 交互

- 点击事件卡片或月历事件标签后，从页面右侧滑入；
- 抽屉覆盖页面右侧区域，不使用居中弹窗；
- 支持关闭按钮、点击遮罩关闭和 `Esc` 关闭；
- 抽屉内部独立滚动；
- 关闭抽屉后保留当前月份、选中日期、分类和筛选条件。

### 7.2 通用信息

根据数据存在情况展示：

- 事件名称；
- 事件分类和子类型；
- 市场或国家/地区；
- 北京时间；
- 数据源原始日期/时间；
- 数据源来源：`Longbridge`；
- 数据更新时间；
- 股票事件的股票名称、代码和市场；
- 自选/持仓来源标签。

Longbridge 的标准事件字段包含 `id`、`symbol`、`market`、`counter_name`、`event_type`、`activity_type`、`date`、`datetime`、`content`、`currency`、`star`、`financial_market_time` 和 `data_kv` 等。[事件字段说明](https://open.longbridge.com/docs/market/calendar/macro-calendar)

### 7.3 类型专属信息

#### 经济数据

- 指标名称；
- 数据所属期间；
- 实际值；
- 预测值；
- 前值；
- 修正值；
- 单位；
- 币种；
- Longbridge 返回的内容和扩展键值。

#### 财报

- 报告期；
- 财报发布日期；
- 盘前/盘后/盘中；
- EPS 实际值和预测值；
- 营收实际值和预测值；
- 其他 `data_kv` 字段。

#### 分红

- 除息日；
- 派息日；
- 记录日（数据存在时）；
- 每股分红金额；
- 币种；
- 分红类型。

#### 拆合

- 拆股/合股类型；
- 生效日期；
- 拆合比例；
- 其他公司行动数据。

#### 休市

- 休市日期；
- 市场；
- 全日/半日市；
- 休市名称或内容。

### 7.4 字段缺失原则

- 缺失字段隐藏，不显示空白占位行；
- 不以 `0`、空字符串或默认值填充缺失数据；
- 没有具体时间时显示“全日”；
- 不显示事件生命周期状态；
- 不承诺展示 Longbridge 未提供的原始来源链接。

## 8. 筛选器

筛选器通过顶部漏斗按钮打开，筛选结果同时影响月历和右侧时间线。

### 8.1 市场

可选项根据当前分类动态展示：

- 财经事件：US、HK、SH、SZ；
- 休市：US、HK、CN。

默认选择当前分类支持的全部市场。

### 8.2 股票来源

只对财报、分红、拆合分类展示：

- 自选股；
- 持仓股。

默认选择两者。宏观和休市分类不显示该筛选项。

### 8.3 重要性

只对 Longbridge 返回 `star` 的事件提供筛选：

- 高重要性：`star = 3`；
- 中重要性：`star = 2`；
- 低重要性：`star = 1`；
- 未提供评级的事件不强行映射等级。

默认选择全部重要性。重要性只表示潜在影响程度，不是事件状态。

### 8.4 筛选行为

- 多个筛选条件使用 AND 关系；
- 同一筛选器内多个选项使用 OR 关系；
- 关闭筛选器后保留已选条件；
- 切换顶部分类时，清理不适用于新分类的筛选条件；
- “重置筛选”恢复该分类默认条件。

## 9. 日期、时间与时区

### 9.1 页面时区

- 页面主时间统一为 `Asia/Shanghai`；
- 页面顶部显示北京时间和 `GMT+08:00`；
- 后端存储带时区时间或 UTC 时间，前端统一转换；
- 不手工固定美东、香港等市场与北京时间的时差；
- 夏令时由时区库处理。

### 9.2 时间显示

- `datetime` 存在且有效：展示北京时间，例如 `08 月 12 日 20:30`；
- 只有日期：展示 `全日`；
- 不从事件类型或交易时间自行推算缺失时间；
- `financial_market_time` 存在时，额外展示盘前、盘后或盘中信息；
- 详情可同时展示数据源提供的原始时间字段。

### 9.3 日期归属

事件按照转换后的北京时间日期归属到月历单元格和右侧日期分组。对于仅有日期的事件，使用数据源日期，不进行跨日推算。

## 10. Longbridge 数据接入要求

### 10.1 接入原则

- 所有 Longbridge 请求只在后端执行；
- API 凭证只保存在后端数据源配置；
- 前端不能读取 API Key、Access Token 或完整授权头；
- Longbridge 数据源只服务事件日历，不参与现有业务数据源切换；
- 不修改扶摇数据源的 `is_active` 状态、凭证或请求链路；
- 事件日历按 `provider_type=longbridge` 选择 Longbridge，即使其未被设为全局 active；
- 日历页面不得逐条调用第三方接口；
- 后端按分类、市场和日期范围批量查询；
- 保留 Longbridge 原始事件 ID 和原始扩展数据，便于排查字段变化。

### 10.2 逻辑适配器接口

后端适配器至少提供以下逻辑能力，具体类名遵循项目现有数据源适配器风格：

```python
get_calendar_events(
    category: Literal["macro", "earnings", "dividend", "split", "closed"],
    start: date,
    end: date,
    markets: list[str] | None = None,
    symbols: list[str] | None = None,
) -> list[CalendarEvent]
```

适配器内部负责将 Dibobo 分类映射为 Longbridge 的 `macrodata`、`report`、`dividend`、`split` 和 `closed` 查询。不得让前端依赖 Longbridge 原始字段命名。

### 10.3 休市与半日市

休市数据优先使用 Longbridge 财经日历中的 `closed` 类别；半日市使用 Longbridge 交易日历返回的半日交易日数据进行补充或校验。交易日接口返回完整交易日和半日交易日列表。[Longbridge 交易日接口](https://open.longbridge.com/docs/market/trade-days)

周末不应被重复创建为普通休市事件，除非 Longbridge 明确返回对应事件。

### 10.4 原始数据保存

原始响应应保存到事件扩展字段中，至少保留：

- provider：`longbridge`；
- provider event ID；
- 原始 category；
- 原始 symbol、market、counter_name；
- 原始 event_type、activity_type；
- 原始 date、datetime、date_type；
- 原始 content、currency、star；
- 原始 financial_market_time；
- 原始 data_kv；
- observed_at；
- last_synced_at。

### 10.5 数据源限制

Longbridge 标准事件结构没有统一的 `source_url` 字段。V1 只展示数据来源名称和更新时间，不承诺每个事件都有可跳转的原始链接。

## 11. 规范化事件模型

以下是产品层逻辑模型。实现可以复用现有 `calendar_events`、`calendar_event_sources` 和 `calendar_sync_runs` 表，但 API 行为必须符合本 PRD。

### 11.1 `CalendarEvent`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string/UUID | 是 | Dibobo 内部事件 ID |
| `provider` | string | 是 | 固定为 `longbridge` |
| `provider_event_id` | string | 否 | Longbridge 事件 ID |
| `category` | enum | 是 | `macro`、`earnings`、`dividend`、`split`、`closed` |
| `event_type` | string | 否 | 供应商事件类型 |
| `title` | string | 是 | 规范化标题 |
| `market` | string | 否 | US、HK、SH、SZ、CN |
| `country_or_region` | string | 否 | 国家/地区名称 |
| `symbol` | string | 否 | 股票代码 |
| `security_name` | string | 否 | 股票名称 |
| `event_date` | date | 是 | 事件日期 |
| `event_datetime` | datetime | 否 | 事件具体时间，带时区 |
| `timezone` | string | 是 | 原始事件时区或推断时区 |
| `all_day` | boolean | 是 | 是否为全天事件 |
| `financial_market_time` | string | 否 | 盘前/盘后/盘中等 |
| `importance` | integer/null | 否 | Longbridge `star`，1-3 |
| `period` | string | 否 | 数据所属期间/报告期 |
| `actual_value` | string | 否 | 实际值 |
| `forecast_value` | string | 否 | 预测值 |
| `previous_value` | string | 否 | 前值 |
| `revised_value` | string | 否 | 修正值 |
| `unit` | string | 否 | 单位 |
| `currency` | string | 否 | 币种 |
| `content` | string | 否 | Longbridge 内容描述 |
| `extra_data` | JSON | 是 | 未标准化的原始扩展数据 |
| `source_name` | string | 是 | `Longbridge` |
| `last_synced_at` | datetime | 是 | 最近同步时间 |

V1 不向前端返回或展示事件生命周期 `status` 字段。若数据库已有该字段，只允许作为内部同步兼容字段，不能用于用户界面、筛选或排序。

### 11.2 来源标签

来源标签由查询时动态计算，不写入供应商事件主记录：

```text
scope_tags = ["watchlist"]
scope_tags = ["holding"]
scope_tags = ["watchlist", "holding"]
```

宏观和休市事件的 `scope_tags` 为空。

### 11.3 去重规则

优先使用以下键去重：

1. `provider + provider_event_id`；
2. `category + market + symbol + event_date + event_type`；
3. 对没有股票的宏观事件使用 `category + market/country + event_date + title + period`；
4. 同一事件的不同 scope 只合并标签，不复制卡片。

## 12. 后端 API 边界

以下 API 为推荐边界，路径遵循项目现有 `/api` 风格。

### 12.1 查询事件

```http
GET /api/calendar/events
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `category` | string | 是 | `macro`、`earnings`、`dividend`、`split`、`closed` |
| `from` | `YYYY-MM-DD` | 是 | 查询起始日期 |
| `to` | `YYYY-MM-DD` | 是 | 查询结束日期 |
| `markets` | string | 否 | 逗号分隔的市场 |
| `scope` | string | 否 | `watchlist`、`holding`、`all` |
| `importance` | string | 否 | 逗号分隔的 1、2、3 |
| `cursor` | string | 否 | 时间线分页游标 |
| `limit` | integer | 否 | 单次返回数量 |
| `refresh` | boolean | 否 | 是否绕过缓存重新同步 |

约束：

- `from` 不得晚于 `to`；
- `category` 不合法时返回 400；
- `markets` 中不允许出现不属于该分类的市场；
- 公司事件必须基于当前用户本地自选/持仓集合过滤；
- 不接受前端传入 `user_id`；
- 结果应包含按日期分组所需的排序信息。

建议响应结构：

```json
{
  "category": "macro",
  "from": "2026-08-01",
  "to": "2026-08-31",
  "timezone": "Asia/Shanghai",
  "items": [],
  "groups": [],
  "next_cursor": null,
  "last_synced_at": "2026-08-15T09:20:00Z",
  "data_source": {
    "name": "Longbridge",
    "state": "ready"
  }
}
```

### 12.2 查询详情

```http
GET /api/calendar/events/{event_id}
```

返回规范化事件和类型专属字段。详情接口不得重新调用前端可见的第三方接口；如需要刷新数据，由后端适配器处理。

### 12.3 查询筛选项

```http
GET /api/calendar/filters?category=macro
```

返回当前分类可用的市场、来源和重要性选项。前端不硬编码供应商返回的市场列表，但可以硬编码产品支持的分类和标签文案。

### 12.4 手动刷新

```http
POST /api/calendar/refresh
```

请求体：

```json
{
  "category": "macro",
  "from": "2026-08-01",
  "to": "2026-08-31",
  "markets": ["US", "HK", "SH", "SZ"]
}
```

刷新接口只允许后端使用已配置的 Longbridge 数据源，不接收任何供应商凭证。

## 13. 数据刷新、缓存与异常

### 13.1 刷新规则

- 首次进入页面查询当前分类和当前月份；
- 切换分类、月份、日期或筛选条件时查询对应范围；
- 用户点击刷新时强制重新同步当前查询范围；
- 不做 WebSocket 实时推送；
- 不做前端定时轮询；
- 页面顶部显示最近一次成功同步时间。

### 13.2 缓存建议

- 按 `provider + category + from + to + markets` 缓存；
- 公司事件查询还需纳入当前用户证券集合版本；
- 缓存命中时正常展示，并显示缓存对应的更新时间；
- 手动刷新失败时可保留最近一次成功缓存，但必须显示数据源异常提示；
- 缓存不得跨用户共享包含股票范围的结果。

### 13.3 异常场景

| 场景 | 页面行为 |
|---|---|
| 未配置 Longbridge | 显示数据源未配置，引导前往设置 |
| 鉴权失败 | 显示授权失效和重新配置提示 |
| 请求超时/服务不可用 | 保留可用缓存并显示重新加载 |
| 频率受限 | 显示稍后重试，不连续自动重试 |
| 返回字段缺失 | 隐藏对应字段，其他字段继续展示 |
| 返回格式变化 | 记录后端错误，页面不白屏 |
| 没有事件 | 月历无标签，右侧列表显示列表级空状态 |
| 股票无法匹配 | 不展示为公司事件，并记录同步日志 |

## 14. 前端状态与交互验收

### 14.1 默认状态

打开 `/calendar` 后：

- 分类：经济数据；
- 月份：当前北京时间月份；
- 选中日期：当前北京时间日期；
- 市场：该分类全部支持市场；
- 重要性：全部；
- 公司事件来源：自选股和持仓股全部；
- 右侧列表：从当前日期开始。

### 14.2 联动验收

1. 切换顶部分类后，月历标签和右侧时间线同时更新。
2. 切换月份后，月历显示目标月份，选中目标月份 1 日，列表从该日开始。
3. 点击日期后，该日期高亮，右侧列表从该日开始。
4. 点击“今天”后恢复默认当前日期。
5. 应用筛选后，月历和右侧列表只展示符合条件的事件。
6. 点击月历标签或右侧卡片后打开右侧详情抽屉。
7. 关闭详情抽屉后，页面筛选和日期状态不丢失。
8. 右侧列表可以跨月加载更多事件。

### 14.3 展示验收

1. 经济数据卡片不显示股票字段。
2. 财报、分红、拆合卡片显示股票名称和代码。
3. 同一股票同时属于自选和持仓时只展示一张卡片，并显示两个标签。
4. 休市卡片显示市场和全日/半日市，不显示重要性。
5. 没有事件的月历日期保持空白。
6. 没有具体时间的事件显示“全日”。
7. 缺失值不显示为 `0` 或空字符串。
8. 不出现“已发布”“已完成”“预计”等事件状态标签。
9. 详情抽屉从页面右侧滑入，而不是居中弹出。

## 15. 安全与非功能要求

### 15.1 安全

- 所有日历接口要求登录；
- 后端根据当前会话确定用户；
- 不信任前端传入的用户 ID；
- Longbridge 凭证只保存在后端；
- 日志不得记录 Access Token、App Secret 或完整 Authorization；
- 公司事件查询不得跨用户返回股票范围或缓存结果。

### 15.2 性能

- 月历查询应优先命中后端缓存；
- 不允许为每一张卡片逐个请求 Longbridge；
- 右侧时间线采用分页或游标；
- 详情抽屉加载不应阻塞月历首屏；
- 前端只渲染当前可见范围和已加载事件。

### 15.3 可观测性

后端同步日志至少记录：

- provider；
- category；
- market；
- 查询时间范围；
- 开始和结束时间；
- 请求成功/失败；
- 获取数量；
- 新增、更新、去重数量；
- 使用缓存与否；
- 错误类型和安全的错误摘要。

## 17. 开发与联调基线

当前开发与联调按以下已确认内容执行：

- 本 PRD 取代旧版事件日历 PRD；
- V1 只实现经济数据、财报、分红、拆合、休市；
- 不实现 IPO、政策、突发新闻、股东会议和提醒；
- 不展示事件状态；
- 使用 Dibobo 本地自选股和持仓股范围；
- 详情从右侧滑入；
- 月历无事件日期保持空白；
- 扶摇继续承载现有业务接口，Longbridge 仅承载事件日历，两个数据源并存运行；
- 本版本作为当前开发与联调基线，后续变更需同步更新需求与验收标准。
