# Dibobo 前端样式与阅读体验审查

审查日期：2026-09-08。基于当前工作树，包含已有的资讯页、应用框架未提交改动。本次交付问题分析和优化方案，未修改前端业务代码。

## 结论

用户提出的两类问题都存在，而且互相放大：视觉规范尚未真正进入所有页面，小字号和文字透明度叠加后降低阅读体验；固定高度布局又让用户在小屏或缩小后的布局视口中难以访问内容。

当前项目已有 UI 原子组件、公共 Pattern、颜色变量和部分排版变量。主要缺口是组件覆盖、变量正确生效以及使用约束。字体族已基本集中，分散更严重的是字号、字重、行高、文字色及其透明度。

优先处理以下五项：

1. 修复自选与组合列表在窄屏被压到零高度，以及弹窗在低高度视口被裁切的问题。
2. 修复 `cn()` 合并自定义字号类时误删字号的问题。
3. 清理承担信息作用的半透明文字，统一正文、标签、表格和元信息的字号。
4. 迁移现有页面到可复用的卡片、工具栏、表格单元格和弹窗布局。
5. 给上述规则建立自动检查，避免页面迭代继续新增局部样式。

## 范围与证据口径

- 静态扫描 `frontend/src` 中 68 个非测试 TSX 文件、6 个 CSS 文件，并检查路由、`cn()`、依赖与检查脚本。源码计数包含潜在未使用组件，表示样式定义分散程度，不等于独立缺陷数量。
- 本地启动当前 Vite 工程，在 Chromium 中检查 13 个实际页面路由：9 个导航页面、3 个股票详情入口、登录页。覆盖 1440×1000 与 390×844，并补查全球市场、数据源页签和新增自选、日记、数据源、持仓弹窗。
- 对自选、组合、雷达补查 1280×720、720×500、320×568。720×500 是较小的布局视口检查，不能等同于已经完成真实浏览器 200% 缩放验收。
- 浏览器使用与当前 Schema 对齐的本地示例 API 响应，未提交业务写请求；第三方 iframe 内容未联网加载。数据仅用于检查布局和文本展示。
- 对比度来自浏览器计算后的文字色、祖先背景与透明度合成。下文重点采用纯色背景的可复核样本；渐变、伪元素、装饰文字和禁用控件不作为简单批量判定依据。本次不是完整 WCAG 合规认证，也未执行全部业务 E2E。
- 现有历史方案 `Dibobo-Frontend-Optimization-Plan.md` 修订于 2026-08-16，部分结论已经过时：当前资讯和雷达已有实现，复盘仍是占位页。本报告使用重新扫描的当前数据。

## 1. 工程现状：公共能力存在，但尚未统一使用

| 检查项 | 当前结果 | 影响 |
| --- | ---: | --- |
| 任意字号 `text-[数字px/rem/em]` | 235 处、41 种字面写法 | 页面调整需要跨文件搜索 |
| 按 15px 根字号换算后的不同数值 | 36 种 | 部分不同写法甚至得到同一字号 |
| 上述任意字号中小于 12px | 103 处 | 还不包含 `text-xs`、语义类和 CSS 定义的小字号 |
| `text-xs` | 29 处 | 实际为 11.25px |
| 已定义的语义字号 | 10 个 token，源码中仅 28 处对应类使用 | 已创建规范但覆盖不足，且部分使用会被 `cn()` 删除 |
| 投资日记独立 `font-size` 声明 | 16 处 | JSX 看似无任意字号，实际重复转移到了 CSS |
| `PageHeader` | 自选、日记两处业务使用 | 其他头部需按真实场景补充变体，不能全部套大标题 |
| Feature 内 `!text-[12px]` | 12 处 | 按钮、弹窗尺寸契约不足，页面不断补覆盖 |
| 相同卡片外观链 | 7 处，其中公共组件 4 处、Feature 3 处 | 应共用卡片外观定义，避免创建平行卡片系统 |

保留现有基础：`Card` 已有 flat/raised/deep/dashed 变体；`Button`、`Tabs`、`FormField`、`Pagination`、异步状态和 `DataTable` 都可继续扩展。`OverviewPanel` 已复用总览面板外壳，日记阅读区正文也已有较好的对比度与较大字号，不需要全部推倒重做。

### 1.1 自定义字号被样式合并工具误删——应先修复

依据：`frontend/src/lib/utils.ts:5` 直接使用默认 `twMerge`，没有配置项目的自定义字号名称。

使用本地已安装依赖复现：

```text
输入：text-table font-medium text-market-up
输出：font-medium text-market-up

输入：text-body font-semibold text-foreground
输出：font-semibold text-foreground

输入：text-caption text-muted-foreground
输出：text-muted-foreground
```

实际影响：`portfolio-rail.tsx:117,125` 的盈亏值，`portfolio-header.tsx:164` 的汇总数字。这里的 `text-table`、`text-title-sm` 经 `cn()` 后消失，浏览器退回继承字号。直接写在 `className` 中、不经过 `cn()` 的同名类则可生效，所以同类信息会出现不一致。

优化：在现有 `cn()` 中通过 `extendTailwindMerge` 将 10 个 token 注册为字号组；为“字号与颜色同时保留”“后传字号正确覆盖前传字号”建立小范围测试。本地验证以下配置能保留字号与颜色并正确消除互斥字号：

```ts
const merge = extendTailwindMerge({
  extend: {
    classGroups: {
      'font-size': [{ text: [
        'caption-xs', 'caption', 'label', 'table', 'body-sm',
        'body', 'title-sm', 'title', 'heading', 'display',
      ] }],
    },
  },
});
```

这是方案示例，尚未写入应用。实施后还要检查依赖这些 token 的页面，因为恢复正确字号本身会改变布局。

### 1.2 样式层级与语义类仍有冲突

`styles.css:238` 的 `.eyebrow` 位于未分层 CSS 中，设置了颜色；`page-header.tsx:21` 又加 `text-primary/90`。浏览器实测该节点仍为 `rgb(155,144,132)`，橙色工具类被覆盖。`styles.css:233` 的 `.font-display` 同样在未分层规则中强制字重。

优化：基础规则、组件规则、工具规则明确进入对应 CSS layer；排版类负责字形、字号、行高，语义颜色负责颜色。避免用一个类同时锁定所有属性，再让页面尝试覆盖。

### 1.3 表格、详情框架与页面高度重复实现

- `watchlist-table.tsx:104,132` 自行实现外壳、表头、吸顶、行、加载态、排序、选择与分页连接；组合和雷达使用 `components/data-table.tsx`。表格字号、行高和背景需改两套。
- `watchlist/stock-detail-page.tsx:25` 与 `portfolios/portfolio-stock-detail-page.tsx:25` 重复 iframe 工具栏、返回按钮、异常提示和高度；雷达已经复用自选详情，组合仍另写一套。
- `styles.css:442`、`radar.css:1`、`journals.css:2`、`calendar.css:6`、`news.css:2` 各自计算页面高度，混用 `vh`、`dvh` 与 68/108/124/132/148px 等外壳扣减值。
- `Card` 默认 `interactive: true`（`components/ui/card.tsx:21`），静态信息卡也获得 hover 阴影反馈。

优化应收敛稳定视觉和布局职责，业务选择、排序、列定义留在 Feature。日历格子、图表以及日记阅读布局可保留专用结构，共享排版和颜色即可。

## 2. 可读性与操作体验：已经确认的具体问题

### 2.1 根字号和字号 token 一起偏小

依据：`styles.css:132–141,151`。

| 当前定义 | 实际 CSS 像素（根字号 15px） |
| --- | ---: |
| `text-caption-xs: .65rem` | 9.75 |
| `text-caption: .7rem` | 10.5 |
| `text-label` / `text-xs: .75rem` | 11.25 |
| `text-table: .8125rem` | 12.19 |
| `text-body-sm` / `text-sm: .875rem` | 13.125 |
| `text-body: .9375rem` | 14.06 |

很多业务标签、时间、股票代码被按“很小的附属信息”处理，但这些信息是投资工作台实际需要反复阅读的内容。仅新增 Typography 组件而保留这些尺寸，不能解决用户反馈。

### 2.2 主要问题来自文字再降透明度，而非深色背景本身

当前 `--muted-foreground: #9b9084` 在 `--card: #1c2026` 上约 **5.23:1**，在主背景 `#111317` 上约 **5.95:1**。不应将所有深底灰字一概判为不可读。

但降低透明度后，可读性明显下降：

| 实际位置 | 实测字号 | 实测对比度 | 代码依据 |
| --- | ---: | ---: | --- |
| 总览卡片更新时间 | 11px | 3.28:1 | `overview/overview-panel.tsx:53`，`text-muted-foreground/70` |
| 指数卡的涨跌额、成交额、最高、最低标签 | 11px | 2.74:1 | `overview/index-card.tsx:45` 起，`/60` |
| 总览涨跌分布的刻度与说明 | 10px | 约 2.53:1 | `overview/market-breadth-card.tsx:73`，`/55` |
| 自选筛选面板的辅助说明 | 10.5px | 约 2.74–3.01:1 | `components/patterns/filter-panel.tsx:34–36` |
| 投资组合汇总指标标签 | 约 12.19px | 3.28:1 | `portfolios/portfolio-header.tsx:159` |
| 组合选中卡片上的红色盈亏 | 15px | 4.22:1 | `portfolios/portfolio-rail.tsx:100–125`，红字叠在橙色选中底上 |
| 日记列表字数与序号 | 10.5px | 约 2.77–2.83:1 | `journals/journals.css:240` 起，58% 混合文字色 |
| 日记列表更新时间 | 12px | 约 3.94–4.19:1 | `journals/journals.css:219` 起，78% 混合文字色 |
| 数据源“能力识别”、API KEY 标签 | 9.75px | 2.74:1 | `settings/data-source-settings.tsx:291,304` |
| 数据源测试时间 | 10.5px | 约 2.70:1 | `settings/data-source-settings.tsx:383` |
| 登录页底部说明 | 10.5px | 2.03:1 | `auth/login-page.tsx:94`，`text-paper/25` |

普通文本对比度应至少 4.5:1，大字至少 3:1；此处列出的这些小字应按普通文本检查。字号建议属于本项目阅读体验规范，WCAG 并未简单规定“所有字必须达到 16px”。参考 [W3C：最低文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

修复重点还包括公共组件：`Pagination:50` 使用 `text-caption + /60`，`Tabs` 的 underline 非选中项使用 `/60`，Input/Textarea placeholder 使用 `/70`。只修业务页面会留下这些共性问题。

### 2.3 固定高度导致内容不可见，不能靠加大字号解决

| 场景 | 浏览器实测 | 影响 |
| --- | --- | --- |
| 自选，390×844 | 表格卡片总高 2px，内容区 `clientHeight = 0` | 列表只剩边线，无法正常浏览与操作 |
| 投资组合，390×844 | 持仓工作区总高 2px，内容区 `clientHeight = 0` | 摘要卡可见，持仓表及操作入口被裁切 |
| 自选与组合，720×500 | 同样压缩到 2px 外壳 | 低高度和较小布局视口下可复现 |
| 雷达，320×568 | 结果区只剩约 85px | 仅露出标题和部分时间，表格及操作区被裁切 |
| 雷达，720×500 | 结果区约 13px | 主体结果几乎不可访问 |
| 自选，1280×720 | 表格滚动区约 118px | 尚能滚动，但有效数据阅读空间很少 |

根因：固定页面高度 + 上方多块 `shrink-0` 内容 + 下方 `flex-1 min-h-0 overflow-hidden`。上方组件换行变高后，下方被压缩。主要依据为 `styles.css:442`、`watchlist-table.tsx:104`、`portfolios-page.tsx:83`、`portfolio-holdings-workspace.tsx:101`、`radar-page.tsx:271,329`。

此外，自选表格最小宽度 1420px（`watchlist-table.tsx:132`），雷达 1240px（`radar-page.tsx:340`），手机端仍延续大表格。表格可以有局部横向滚动，但不应让整个内容区消失；数据表格有二维布局例外，不能单凭横向滚动就判定违反重排要求。参考 [W3C：重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

### 2.4 弹窗、微型控件需要共同调整

- 持仓弹窗在 720×500 下实测高约 564px，顶部坐标约 -32px，标题、关闭区域和底部保存按钮被裁切。公共 `DialogContent`（`components/ui/dialog.tsx:12–38`）缺少默认最大高度和滚动区域；持仓页（`holding-dialog.tsx:138`）只补宽度。
- 日记弹窗在页面中自行补了 `max-h-[92vh] flex-col overflow-hidden`（`journal-dialog.tsx:89`），说明公共弹窗没有覆盖这类稳定需求。数据源弹窗也应跟随迁移并复查长表单。
- 数字步进按钮为 `h-4 w-6`，实际约 **22.5×15px**（`holding-form-controls.tsx:137,145`），且默认隐藏，hover/focus 后才显示。应增大点击区，并提供触摸端持续可见的操作方式；输入框本身可编辑，不能只根据小箭头尺寸直接宣称违反 WCAG，仍需考虑等效控件例外。参考 [W3C：目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 4. 建议采用的统一规范

### 4.1 排版

根字号改为 `100%`，尊重浏览器默认字号；以默认 16px 环境设计下列规范。使用 rem，并同时定义行高和字重。对于受控紧凑表格可保留单独 density，但不要继续自由定义字体尺寸。

| 语义 | 建议默认大小 | 行高/用途 |
| --- | --- | --- |
| body | 16px / 1rem | 1.6–1.75，普通正文 |
| body-sm / table | 14px / .875rem | 1.5，表格与紧凑说明 |
| label | 14px / .875rem | 1.4–1.5，表单与筛选标签 |
| caption | 13px / .8125rem | 1.45，时间、来源、代码等元信息 |
| caption-xs | 12px / .75rem | 仅用于次要图表刻度；避免承担关键说明 |
| title-sm | 18px / 1.125rem | 卡片或分组标题 |
| title | 20px / 1.25rem | 面板标题 |
| heading | 28–32px | 页面标题，按场景选择紧凑变体 |
| display | 32–40px | 少量关键指标 |

标准模式建议：正文 16px、表格 14px、常用按钮文字 14px；紧凑模式主要收紧 padding 和行高。不要通过让全部重要信息退回 10–11px 来增加信息密度。

建议提供轻量 `Text`/`Heading` 或等价的语义类+CVA；FormLabel、TableCell、Metric 等稳定结构由组件绑定排版。纯粹一段文本不必都新增 JSX 包装，核心是只有一个规范来源。

字体族继续复用现有中文回退栈。当前仓库没有实际加载 Inter 字体文件的声明，仅在 font stack 中列出名字，因此应在 Windows 中文字体回退环境检查，不应假设所有机器都显示 Inter。业务数字使用独立 `numeric` 语义和 tabular-nums，避免继续把 `font-mono` 当作“所有数字”的样式标识。

### 4.2 颜色

保留现有深色背景体系即可先完成修复。建议分开背景层级和文字重要程度：

- 主正文：可保留 `#f2ece4`。
- 次要文字：可采用 `#b8c1cc`，在当前卡片底上约 8.99:1；也可以保留已达标的原色，但取消降透明度。
- 三级元信息：设置独立、不透明、通过对比度验证的 token，避免每个页面使用 `/40`、`/55`、`/65`。
- 弱化可以通过位置、字重和间距表达。装饰序号允许更弱，但时间、股票代码、表单说明、数据源消息不能按装饰处理。
- 上涨、下跌、警告、成功、选中、placeholder 分别验证正常/悬停/选中背景。尤其修复选中组合中的红字，不只检查红字在默认卡片底上的对比度。
- 如果需要浅色模式，在上述 token 收敛后增加 light/dark 两套映射；不要先复制一整套 Feature CSS。

### 4.3 组件与布局职责

| 复用方向 | 具体做法 | 优先迁移 |
| --- | --- | --- |
| 页面布局 | `PageContainer` 保留宽度职责；增加 Workspace 布局契约统一自然滚动/桌面内部滚动；外壳高度与内容 padding 用 CSS 变量统一 | 自选、组合、雷达 |
| 页面/面板头 | 扩展 `PageHeader` 的标准/紧凑形式和 actions；`OverviewPanel` 继续作为总览专用头部 | 设置、雷达；日历/资讯使用工具栏形态 |
| 卡片 | 复用已有 `Card.variant`，默认 `interactive=false`；外壳定义从公共组件与 Feature 双向收敛 | FilterPanel、列表外壳、统计卡 |
| 指标与行情单元格 | `Metric`、`InstrumentCell`、`ChangeValue`、`Timestamp`，统一标签/值/辅助信息和涨跌符号 | 总览、组合、自选、雷达 |
| 表格 | 扩展 `DataTable` 的 density、嵌入外观、工具栏；先统一外观，再迁移自选的选择/排序/固定列能力 | 自选、持仓、雷达 |
| 筛选 | `FilterPanel` 统一文字和视觉；`FilterToolbar` 处理响应式排列，保留每页筛选字段 | 自选、持仓、日历 |
| 控件与弹窗 | Button/Input/Select 共享 density；Dialog 默认有最大高度、正文滚动区和可访问的操作栏 | 所有表单弹窗 |
| 外部内容 | `ExternalContentFrame` 统一来源、返回、新窗口、加载和提示区域 | 资讯与三个详情入口 |

避免机械合并业务差异：自选的批量选择、持仓的清仓记录、雷达的加入自选动作应保留 Feature 实现；行业虚拟表格与普通管理表格不必强制使用同一行模型。

### 4.4 响应式与缩放

- 窄屏或低高度视口切换自然文档滚动，取消让主体内容无下限收缩的固定高度链。
- 桌面保留内部滚动时，为表格视口保证可用最小高度；不足时改为整页滚动。
- 移动自选/持仓/雷达展示名称、价格、涨跌或盈亏、主操作；其他字段展开查看。支持真正需要的大表格模式，不依赖左右两个固定列夹住仅剩的一点空间。
- 月历在手机上可切换日程列表；月格显示事件数量/标记，点击后展示完整标题，避免把标题缩小到只剩一个字。
- Dialog 使用 `max-height: calc(100dvh - 2 * gutter)`，内容区可滚动，保证标题、关闭、确认按钮始终可访问。移动控件目标尺寸可按 44px 产品标准设计，桌面小图标也应保留足够点击区。
