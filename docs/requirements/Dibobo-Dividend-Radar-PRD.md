## 1. 文档目的

本文定义红利雷达的产品目标、股票范围、筛选指标、手动同步流程、每日后台任务、自选管理接入、Longbridge 数据接口、页面状态、API 边界、数据持久化、异常处理和验收标准。

技术实现可以调整模块、类名、表名和接口内部结构，但不得改变本文定义的：

- 股票池范围；
- 筛选边界和缺失值规则；
- 默认策略；
- 手动同步与每日任务的职责；
- Longbridge 数据源隔离；
- 添加到本地自选管理的行为。

## 2. 背景与问题定义

当前应用已经预留红利雷达入口，但尚未形成可用的筛选和结果展示能力。用户希望快速从沪深 A 股中发现满足基础红利和估值条件的股票，并将感兴趣的股票加入已有的自选管理。

本次需求的核心问题是：

1. 用市值、股息率、市净率和市盈率建立可解释的股票筛选条件；
2. 让用户能够临时调整条件并立即同步得到结果；
3. 每天在固定时间自动执行一套默认策略，进入页面即可查看最新结果；
4. 让雷达结果可以无缝进入已有本地自选管理；
5. 保证雷达使用 Longbridge，不影响其他模块现有数据源。

## 3. 产品目标与成功标准

### 3.1 产品目标

1. 提供沪深 A 股红利筛选能力，不纳入北交所、ETF、基金和指数。
2. 支持市值、股息率、PB、PE 四类条件的最小值和最大值筛选。
3. 使用包含边界的区间判断，多个条件之间使用 AND 关系。
4. 对缺失指标采用“保留但标记数据不完整”的策略，不因缺失直接排除股票。
5. 默认展示“市值 ≥800 亿元、股息率 ≥4%”的每日结果。
6. 提供手动同步筛选，并将手动条件与每日默认策略分开。
7. 支持一键将雷达股票加入本地自选管理，避免重复添加。

### 3.2 成功标准

- 用户可以在红利雷达页面填写四类指标的最小值和最大值并执行筛选；
- 边界值能够被正确保留，例如市值恰好为 800 亿元的股票满足“市值 ≥800 亿元”；
- 缺失 PB、PE 或股息率的股票不会因为该字段为空而被静默排除；
- 每日 15:30（北京时间）后台任务执行默认策略并保存结果；
- 页面初次打开时优先展示最近一次成功的默认日快照；
- 雷达中的股票点击添加后出现在自选管理，并且同一用户不会产生重复自选记录；
- Longbridge 不可用时，页面显示明确的数据源/刷新状态，不伪造数据，也不自动切换到扶摇、AKShare 或其他来源；
- 总览、持仓、投资组合和自选管理的既有数据源与行为不因本模块上线而改变。

## 4. 用户故事

### 4.1 查看每日默认结果

作为投资研究用户，我希望打开红利雷达就能看到系统每天自动筛选出的高市值、高股息股票，而不需要每次重新输入条件。

### 4.2 手动调整条件

作为投资研究用户，我希望临时填写市值、股息率、PB、PE 的范围并立即同步筛选结果，以便验证不同策略条件。

### 4.3 加入自选

作为投资研究用户，我希望在筛选结果中直接点击“添加自选”，把股票加入现有自选管理，而不需要重新搜索股票代码。

### 4.4 识别数据质量

作为投资研究用户，我希望知道某项指标没有数据，而不是把缺失值误认为 0 或认为该股票不满足条件。

## 6. 股票池与排除规则

### 6.1 股票池

仅允许以下范围：

| 维度                | 规则                           |
| ------------------- | ------------------------------ |
| 资产类型            | A 股普通股票                   |
| 交易所              | 上海证券交易所、深圳证券交易所 |
| Longbridge 市场参数 | `CN`                           |
| 代码后缀            | `.SH`、`.SZ`                   |

明确不纳入：

- 北交所股票（例如 `.BJ`）；
- ETF、LOF、普通基金；
- 指数；
- 港股、美股和其他市场标的。

### 6.2 默认排除

以下股票不得进入结果：

- 股票简称以 `ST` 或 `*ST` 开头的股票；
- 股票简称或状态包含“退市”或“退市整理”的股票；
- 数据源明确标记为停牌、暂停上市或不可交易的股票。

名称判断需要兼容中文空格和大小写差异。状态判断优先使用 Longbridge 返回的标准状态字段；名称判断作为兜底。不能仅因为某个指标缺失就把股票认定为停牌。

## 7. 筛选条件与指标口径

### 7.1 条件清单

| 页面字段 | 内部字段         | Longbridge 指标 | 单位 | 默认最小值 | 默认最大值 |
| -------- | ---------------- | --------------- | ---- | ---------: | ---------: |
| 市值     | `market_cap`     | `marketcap`     | 亿元 |        800 |         空 |
| 股息率   | `dividend_yield` | `divyld`        | %    |          4 |         空 |
| 市净率   | `pb`             | `pbmrq`         | 倍   |         空 |         空 |
| 市盈率   | `pe_ttm`         | `pettm`         | 倍   |         空 |         空 |

说明：

- 市值在页面和产品内部筛选语义中使用“亿元”；适配器先读取 Longbridge 的 `marketcap` 指标元数据，再将产品单位转换为供应商当前声明的单位，不能硬编码某一种单位；
- Longbridge 返回的 `marketcap` 可能是基础货币数值或指标单位数值，适配器必须统一转换为亿元后再展示和执行本地二次判断；
- 股息率按百分数展示，例如 `4.00%` 表示数值 4；
- PB 使用 MRQ 口径；
- PE 使用 TTM 口径；
- 本模块不自行根据财务报表或分红事件重算上述指标，以 Longbridge Screener 返回的标准化指标为准；
- 最新价和涨跌幅属于结果展示字段，不作为本次筛选条件。

### 7.2 输入规则

每个条件支持：

- 最小值，可为空；
- 最大值，可为空；
- 最小值和最大值均为空时，表示不限制；
- 最小值等于最大值时，表示筛选该精确值；
- 最小值大于最大值时，禁止提交并提示修改；
- 只允许输入合法数字，不接受负的市值和股息率；PB/PE 的负值是否有业务意义由 Longbridge 原值决定，页面不擅自改写为 0；
- 空字符串提交为 `null`，不得转换为 0。

### 7.3 区间判断

所有填写的边界均包含在内：

```text
min_value is null or value >= min_value
AND
max_value is null or value <= max_value
```

多个指标之间使用 AND 关系。只要某个有值指标明确不满足区间，股票就被排除。

### 7.4 缺失值规则

用户已确认：缺失指标不主动排除，数据通常应可用，但系统仍必须正确处理空值。

| 指标状态         | 筛选判断 | 结果处理                 |
| ---------------- | -------- | ------------------------ |
| 有值且满足区间   | 通过     | 保留                     |
| 有值但不满足区间 | 不通过   | 排除                     |
| 缺失或无法解析   | 未知     | 保留，并标记“数据不完整” |

结果列表中缺失字段显示“暂无数据”或“—”，不得显示 0、空白或伪造的默认值。数据不完整股票可在完整结果之后展示，但不得被当作明确满足全部条件的股票。

## 8. 默认策略与运行方式

### 8.1 默认策略

默认条件固定为：

```text
市值 >= 800 亿元
股息率 >= 4%
市净率：不限
市盈率：不限
```

默认策略是系统每日任务使用的策略，不因用户在页面上临时修改输入而改变。

### 8.2 手动同步筛选

用户点击“同步筛选”后：

1. 前端提交当前四类筛选条件；
2. 后端同步调用 Longbridge Screener；
3. 后端完成股票池过滤、字段标准化、缺失值处理和分页；
4. 前端展示本次筛选结果；
5. 页面保留当前条件，用户可以继续调整后再次同步；
6. 手动条件不覆盖每日默认策略，也不修改已保存的默认日快照；
7. 请求期间按钮进入 loading 状态，避免重复提交。

手动筛选属于用户主动操作，不创建长时间运行的异步搜索任务，不要求前端轮询任务进度。若 Longbridge 请求超时或失败，返回明确错误状态并保留页面上一次结果。

### 8.3 每日后台任务

系统每天北京时间 15:30 执行一次默认策略：

1. 使用每个用户当前启用的 Longbridge 数据源；
2. 执行默认条件筛选；
3. 过滤股票池和排除项；
4. 获取并标准化结果；
5. 保存该用户最近一次默认日快照；
6. 页面下次打开时优先读取该快照，不在页面请求链路中同步跑全市场筛选。

任务规则：

- 时区固定为 `Asia/Shanghai`；
- 每个用户每天最多生成一份默认日快照；
- 同一用户同一天重复触发时应幂等或复用已有成功结果；
- 手动筛选不改变当日默认快照；
- 任务失败时保留上一份成功快照，并标记为“上次刷新失败/数据可能过期”；
- 没有成功快照时显示空状态和失败原因，不伪造结果；
- 任务不得阻塞页面请求、登录、持仓或其他业务模块。

### 8.4 首次打开页面

页面初始加载顺序：

1. 优先读取最近一次默认日快照；
2. 同时返回快照生成时间、快照状态和数据源摘要；
3. 若没有快照，显示“暂无今日默认结果”，引导用户执行手动同步；
4. 页面初始加载不得自动调用 Longbridge 进行同步筛选；
5. 页面不把手动结果写成默认日快照。

## 9. Longbridge 数据接口可行性

### 9.1 已确认的接口

Longbridge 官方 Screener 文档提供以下能力：

- 搜索接口：`POST /v1/quote/ai/screener/search`；
- 市场参数：`CN`；
- 支持按条件筛选、分页和指定展示指标；
- 返回股票代码、名称、市值、股息率、PE、PB 等字段。

相关官方文档：

- [Screener Search](https://open.longbridge.com/zh-CN/docs/screener/screener-search)
- [Screener Indicators](https://open.longbridge.com/docs/screener/screener-indicators)
- [Screener CLI / Quant](https://open.longbridge.com/docs/cli/quant/screener)
- [Quote Overview](https://open.longbridge.com/docs/quote/overview)

### 9.2 请求条件映射

后端适配器应将页面条件映射为 Longbridge Screener 条件：

| 页面条件 | Longbridge 条件 key |
| -------- | ------------------- |
| 市值     | `marketcap`         |
| 股息率   | `divyld`            |
| 市净率   | `pbmrq`             |
| 市盈率   | `pettm`             |

当前适配器先读取 `GET /v1/quote/ai/screener/indicators` 获取指标单位，再按 Longbridge SDK 实际 wire format 使用 `filters` / `returns`；条件 key 带 `filter_` 前缀。以下以当前中文指标元数据返回 `亿` 为例，因此 1000 亿元提交为 1000；若元数据返回 `bn`，适配器应自动提交 100：

```json
{
  "market": "CN",
  "filters": [
    { "key": "filter_marketcap", "min": "1000", "max": "", "tech_values": {} },
    { "key": "filter_divyld", "min": "4", "max": "", "tech_values": {} }
  ],
  "returns": [
    "filter_prevclose",
    "filter_prevchg",
    "filter_marketcap",
    "filter_salesgrowthyoy",
    "filter_pettm",
    "filter_pbmrq",
    "filter_industry",
    "filter_divyld"
  ],
  "page": 0,
  "size": 20
}
```

实际请求字段以当前 Longbridge SDK/HTTP 响应契约为准；适配器必须集中处理，不允许在页面或业务服务中拼接供应商字段。
基础面指标的 `tech_values` 按当前 SDK wire format 传对象 `{}`；未设置的边界仍需传空字符串。

### 9.3 返回字段标准化

适配器至少尝试标准化以下字段：

| 标准字段         | Longbridge 字段        | 说明                                           |
| ---------------- | ---------------------- | ---------------------------------------------- |
| `thscode`        | `symbol`               | 完整代码，例如 `600000.SH`                     |
| `ticker`         | 由 `symbol` 解析       | 纯数字代码                                     |
| `name`           | `name`                 | 股票简称                                       |
| `market_cap`     | `marketcap`            | 返回基础货币或供应商单位，适配器统一转换为亿元 |
| `dividend_yield` | `divyld`               | %                                              |
| `pb`             | `pbmrq`                | 倍                                             |
| `pe_ttm`         | `pettm`                | 倍                                             |
| `latest`         | `last_done` 或等价字段 | 最新价                                         |
| `change_percent` | `prevchg` 或等价字段   | 当日涨跌幅                                     |
| `industry`       | 若接口提供             | 没有则显示“—”                                  |
| `status`         | 若接口提供             | 用于停牌/不可交易过滤                          |

适配器必须：

- 处理 Longbridge 返回的空值、数字字符串和 `null`；
- 过滤 `.BJ`、ST、*ST、退市和停牌股票；
- 不把缺失指标转换为 0；
- 不把流通市值当作总市值；
- 记录上游响应中的数据时间和抓取时间（如果接口提供）；
- 为后续字段变化保留适配器层测试。

### 9.4 数据源隔离

- 红利雷达只读取当前用户启用的 Longbridge 数据源；
- 没有启用 Longbridge 时，红利雷达显示“请先配置并启用 Longbridge”；
- Longbridge 认证失败、限流、超时和服务异常需要在页面显示可理解的状态；
- 不自动切换扶摇、AKShare 或其他数据源；
- 既有总览、持仓、投资组合和自选管理继续沿用各自当前数据源；
- Longbridge 凭据继续使用现有加密存储和用户隔离机制。

## 10. 页面信息架构与交互

### 10.1 页面入口

- 沿用现有导航中的“红利雷达”；
- 路由：`/radar`；
- 页面标题：`红利雷达`；
- 页面说明：展示满足红利和估值条件的沪深 A 股股票，不提供投资建议。

### 10.2 页面结构

页面从上到下包含：

1. 默认策略摘要：突出显示 `市值 ≥800 亿` 和 `股息率 ≥4%`；
2. 状态提示区：加载、失败、过期和无数据提示；
3. 结果工具栏：结果标题、数据时间、数据源和“开始扫描”按钮；
4. 结果列表：股票信息、指标、行情、所属行业和图标操作按钮；
5. 分页区：当前页、总数和翻页。

### 10.3 筛选面板

当前页面不展示独立筛选面板；页面数据使用每日默认策略（市值 ≥800 亿、股息率 ≥4%）。

“开始扫描”会立即使用默认策略重新请求一次数据，不修改每日任务配置。后续如需开放临时条件筛选，可复用现有筛选接口和通用筛选组件。

### 10.4 结果列表字段

| 展示字段 | 规则                                                           |
| -------- | -------------------------------------------------------------- |
| 股票名称 | 显示最新简称                                                   |
| 股票代码 | 显示纯代码和交易所简称或完整代码                               |
| 最新价   | Longbridge 有值时展示，否则显示“—”                             |
| 涨跌幅   | Longbridge 有值时展示，涨跌使用方向和颜色表达                  |
| 市值     | 亿元，建议保留 2 位小数                                        |
| 股息率   | 百分比，建议保留 2 位小数                                      |
| PB       | 倍，建议保留 2 位小数                                          |
| PE       | TTM 倍数，建议保留 2 位小数                                    |
| 行业     | 有值时展示，无值显示“—”                                        |
| 操作     | 图标按钮：添加自选、查看详情；按钮通过悬浮提示和无障碍标签说明 |

数值缺失统一显示“暂无数据”或“—”，不得以 0 代替。

### 10.5 添加自选交互

1. 用户点击某行“添加自选”；
2. 前端向本地自选管理接口提交该股票的稳定代码、名称和必要基础信息；
3. 添加成功后按钮变为“已在自选”；
4. 已存在于自选的股票初始就显示“已在自选”；
5. 重复添加不创建重复记录，并提示“该股票已在自选管理”；
6. 添加失败时保留“添加自选”按钮并展示错误信息；
7. 本操作不调用 Longbridge 云端自选能力。
8. 用户点击“查看详情”后，复用自选管理的股票详情路由打开该标的详情。

## 11. 数据状态与异常处理

### 11.1 页面状态

| 状态             | 页面行为                                             |
| ---------------- | ---------------------------------------------------- |
| `loading`        | 显示骨架或加载状态，禁用重复提交                     |
| `success`        | 展示结果、总数、生成时间和数据源                     |
| `empty`          | 展示暂无结果及“开始扫描”入口                         |
| `not_configured` | 提示配置并启用 Longbridge                            |
| `stale`          | 展示最近成功结果，同时提示本次刷新失败或数据可能过期 |
| `error`          | 展示错误原因和重试入口，不清空已有可用结果           |
| `partial`        | 结果正常展示，缺失字段标记“数据不完整”               |

### 11.2 后台任务失败

后台任务失败时：

- 不删除最近一次成功快照；
- 更新任务状态、失败时间和错误摘要；
- 页面展示“上次刷新失败，当前为最近成功数据”；
- 不将失败结果当作成功日快照；
- 记录结构化日志，至少包含用户、数据源、任务时间、错误类型和请求阶段。

### 11.3 Longbridge 限流和超时

- 复用现有 Longbridge HTTP 客户端的超时、认证和请求间隔控制；
- 后台任务失败不进行无界重试；
- 手动请求超时后允许用户再次点击重试；
- 同一用户的重复手动请求应在前端 loading 期间阻止，在后端按现有限流规则处理；
- 不使用备用数据源伪造完整结果。

## 12. 后端接口契约

以下为产品层接口契约，具体 URL、字段命名可在实现阶段遵循项目既有约定调整，但语义必须保持一致。

### 12.1 读取默认日快照

```http
GET /api/radar?page=1&page_size=20
```

用途：页面初始加载，读取最近一次默认策略快照。

响应至少包含：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "filters": {
    "market_cap_min": 800,
    "market_cap_max": null,
    "dividend_yield_min": 4,
    "dividend_yield_max": null,
    "pb_min": null,
    "pb_max": null,
    "pe_min": null,
    "pe_max": null
  },
  "result_type": "daily",
  "snapshot_status": "success",
  "generated_at": "2026-08-17T15:35:00+08:00",
  "data_source": {
    "provider": "longbridge",
    "name": "Longbridge"
  }
}
```

### 12.2 手动同步筛选

```http
POST /api/radar/search
```

请求体：

```json
{
  "filters": {
    "market_cap_min": 1000,
    "market_cap_max": 5000,
    "dividend_yield_min": 4,
    "dividend_yield_max": null,
    "pb_min": null,
    "pb_max": 1.5,
    "pe_min": null,
    "pe_max": 15
  },
  "page": 1,
  "page_size": 20
}
```

响应包含：

- `items`；
- `total`、`page`、`page_size`；
- 实际使用的 `filters`；
- `result_type: "manual"`；
- `generated_at`；
- 数据源摘要；
- 每个股票的指标、行情、数据完整性和自选状态。

### 12.3 添加雷达股票到自选

建议复用本地自选管理域的独立入口：

```http
POST /api/watchlist/from-radar
```

请求至少包含：

```json
{
  "thscode": "600000.SH",
  "name": "浦发银行"
}
```

接口必须在服务端校验用户身份、股票代码格式和重复记录，不能只依赖前端按钮状态。

## 13. 数据持久化

### 13.1 默认日快照

系统需要持久化最近一次默认策略结果，至少保存：

| 字段             | 说明                         |
| ---------------- | ---------------------------- |
| `user_id`        | 所属用户                     |
| `data_source_id` | 使用的 Longbridge 数据源     |
| `run_date`       | 任务运行日期                 |
| `filters`        | 默认筛选条件 JSON            |
| `items`          | 标准化结果 JSON 或等价结果表 |
| `total`          | 结果总数                     |
| `status`         | `success`、`failed` 等状态   |
| `generated_at`   | 结果生成时间                 |
| `last_error`     | 最近一次失败摘要，可为空     |

约束：

- 结果属于用户，用户之间不能互相读取；
- 同一用户只保留当前默认日快照即可，历史快照不在本次范围；
- 快照必须带数据源和生成时间；
- 数据源切换后不得复用其他数据源的雷达快照；
- 手动筛选结果不写入默认日快照。

### 13.2 自选管理关系

雷达不创建新的自选数据模型。添加操作使用现有 `WatchlistItem`，以当前用户和稳定股票代码作为唯一性判断。

## 14. 权限、安全与数据隔离

1. 所有雷达 API 必须要求登录；
2. 只读取当前用户启用的 Longbridge 数据源；
3. Longbridge 凭据不得返回前端或写入普通日志；
4. 默认快照按用户隔离；
5. 添加自选只能写入当前登录用户的自选列表；
6. 写操作继续使用项目现有 CSRF 防护；
7. API 错误向前端返回可理解的业务信息，但不暴露密钥、完整上游响应或内部堆栈。

## 15. 非功能要求

### 15.1 性能

- 页面初次打开只读取本地快照，不同步执行全市场 Longbridge 请求；
- 手动筛选使用分页，后端按 Longbridge 支持的页面大小抓取；
- 后台任务不阻塞 API 事件循环；
- 后台任务应避免同一用户同一天的重复执行；
- 结果列表在桌面和移动端均不得造成页面级横向滚动。

### 15.2 可观测性

后台任务至少记录：

- 任务开始、结束和耗时；
- 用户和数据源标识；
- 实际筛选条件；
- Longbridge 请求页数和返回数量；
- 排除数量及主要排除原因；
- 缺失字段数量；
- 成功、失败和错误类型。

日志不得记录 Longbridge 密钥和完整认证头。

### 15.3 可维护性

- Longbridge 字段映射集中在数据源适配器；
- 业务层只使用标准化字段；
- 默认策略集中定义，页面和后台任务复用同一份常量/Schema；
- 手动筛选和每日任务复用同一套筛选服务，避免两套口径；
- 自选添加复用现有自选领域服务，不在雷达中复制一套自选逻辑。

## 18. 当前明确的实现约定

以下约定用于消除开发时歧义：

1. “手动同步筛选”指用户点击按钮后同步得到本次条件结果，不采用旧版长任务轮询流程。
2. “每日 15:30 后台任务”只执行固定默认策略，不读取用户临时修改的筛选表单。
3. 页面初始展示最近一次成功的默认日快照；手动结果只在当前页面会话中展示，不覆盖默认快照。
4. “加入自选”写入 Dibobo 当前用户的本地自选表，不同步 Longbridge 云端自选。
5. 缺失指标不等于不满足条件；只有有值且明确越过边界时才排除。
6. 红利雷达使用 Longbridge，其他模块不因本需求切换数据源。
